title: Building an evaluation harness
description: A runnable eval set, graders that check properties, results recorded with the prompt and model that produced them, and a comparison that tells you exactly which examples changed.
module: production-ai
order: 4
level: expert
minutes: 22
objectives:
  - Design an eval set that catches real regressions
  - Write graders, from exact match to property checks
  - Run an evaluation concurrently, within a cost budget
  - Record results so two runs can be compared example by example
  - Split the set so prompt tuning does not overfit it
---

An evaluation harness is the instrument that makes every other decision in this module possible.
Without one, "the new prompt is better" is a feeling.

JSONL again, for the same reasons as module 2: append a case without rewriting the file, and read
a large set without loading it.

<Callout type="tip">
Start with twenty examples, not two hundred. Include every bug you have actually shipped, a
quarter that must be refused, and a few that are genuinely ambiguous. A small set you curate and
actually run beats a large one you generated and never look at.
</Callout>

## Graders

A grader turns an answer and an expectation into a pass or a fail. Compose several:

<Run id="prod-eval-2" code={`import re

REFUSAL = "I don't know based on the provided documentation."

def grade_refusal(answer, expect, context_ids):
    should_refuse = expect.get("refuse", False)
    refused = answer.strip() == REFUSAL
    if should_refuse:
        return refused, "refused as required" if refused else "answered a question it should refuse"
    return not refused, "answered" if not refused else "refused an answerable question"

def grade_contains(answer, expect, context_ids):
    required = expect.get("contains", [])
    missing = [term for term in required if term.lower() not in answer.lower()]
    return not missing, "all terms present" if not missing else f"missing {missing}"

def grade_citations(answer, expect, context_ids):
    if expect.get("refuse"):
        return True, "not applicable"
    cited = set(re.findall(r"\\[([a-zA-Z0-9_]+)\\]", answer))
    unsupported = cited - set(context_ids)
    if unsupported:
        return False, f"cited unsupplied {sorted(unsupported)}"
    if not cited:
        return False, "no citations"
    wanted = set(expect.get("cites", []))
    if wanted and not (cited & wanted):
        return False, f"cited {sorted(cited)}, expected one of {sorted(wanted)}"
    return True, f"cited {sorted(cited)}"

def grade_length(answer, expect, context_ids):
    limit = expect.get("max_words")
    if limit is None:
        return True, "no limit"
    words = len(answer.split())
    return words <= limit, f"{words} words (limit {limit})"

GRADERS = {
    "refusal": grade_refusal,
    "contains": grade_contains,
    "citations": grade_citations,
    "length": grade_length,
}

expect = {"contains": ["10", "20"], "cites": ["c1"], "max_words": 40}
for answer in ["Use an overlap of 10 to 20 percent [c1].",
               "Use a bit of overlap [c1].",
               "Use 10 to 20 percent [c9]."]:
    verdicts = {name: grader(answer, expect, ["c1", "c2"]) for name, grader in GRADERS.items()}
    passed = all(ok for ok, _ in verdicts.values())
    print(f"{'PASS' if passed else 'FAIL'}  {answer}")
    for name, (ok, note) in verdicts.items():
        if not ok:
            print(f"        {name}: {note}")`} />

Each grader answers one question, so a failure says *which* property broke — which is the
difference between a number that drops and a number you can act on.

## Running it

<Run id="prod-eval-3" code={`import asyncio, json, re, time
from pathlib import Path
from types import SimpleNamespace

REFUSAL = "I don't know based on the provided documentation."

RECORDED = {
    "How much overlap between chunks?": ("Use an overlap of 10 to 20 percent [c1].", ["c1", "c2"]),
    "What dtype for embeddings?": ("Store vectors as float32 [c2].", ["c1", "c2"]),
    "What does E4021 mean?": ("The embedding dimension did not match the index [c3].", ["c3"]),
    "What is the weather in Colombo?": (REFUSAL, []),
    "Who is the CEO?": ("The CEO is not documented here [c1].", ["c1"]),
    "How many documents per request?": ("At most 100 documents [c4].", ["c4"]),
}

class RecordedSystem:
    def __init__(self, responses):
        self.responses = responses
        self.calls = 0
    async def answer(self, question):
        self.calls += 1
        await asyncio.sleep(0.01)
        text, context = self.responses.get(question, (REFUSAL, []))
        return SimpleNamespace(text=text, context_ids=context,
                               usage=SimpleNamespace(input_tokens=900, output_tokens=40))

def grade(answer, expect, context_ids):
    cited = set(re.findall(r"\\[([a-zA-Z0-9_]+)\\]", answer))
    refused = answer.strip() == REFUSAL
    checks = {
        "refusal": refused if expect.get("refuse") else not refused,
        "contains": all(t.lower() in answer.lower() for t in expect.get("contains", [])),
        "citations": True if expect.get("refuse") else (bool(cited) and not (cited - set(context_ids))),
        "length": len(answer.split()) <= expect.get("max_words", 10**6),
    }
    return checks, all(checks.values())

async def run_evaluation(system, examples, *, limit=4, cost_per_call=0.0053):
    semaphore = asyncio.Semaphore(limit)
    started = time.perf_counter()

    async def one(example):
        async with semaphore:
            response = await system.answer(example["question"])
        checks, passed = grade(response.text, example["expect"], response.context_ids)
        return {
            "id": example["id"], "question": example["question"], "answer": response.text,
            "checks": checks, "passed": passed,
            "input_tokens": response.usage.input_tokens,
            "output_tokens": response.usage.output_tokens,
        }

    results = await asyncio.gather(*(one(e) for e in examples))
    return {
        "results": results,
        "passed": sum(r["passed"] for r in results),
        "total": len(results),
        "seconds": round(time.perf_counter() - started, 3),
        "cost_usd": round(len(results) * cost_per_call, 4),
    }

EXAMPLES = [json.loads(line) for line in Path("eval.jsonl").read_text().splitlines() if line.strip()]
system = RecordedSystem(RECORDED)
report = await run_evaluation(system, EXAMPLES)

print(f"{report['passed']}/{report['total']} passed in {report['seconds']}s, "
      f"about \\u0024{report['cost_usd']}")
print()
for result in report["results"]:
    if not result["passed"]:
        failed = [name for name, ok in result["checks"].items() if not ok]
        print(f"FAIL {result['id']}  {failed}")
        print(f"     Q: {result['question']}")
        print(f"     A: {result['answer']}")`} />

One example fails — the system answered a question it should have refused, and cited a chunk to do
it. That is precisely the failure an eval set exists to catch.

## Record everything

A result without its provenance cannot be compared to anything:

<Callout type="ai" title="Why this matters for AI">
The eval-set hash is the one people forget, and it is the one that ruins comparisons. If somebody
adds three easy examples between two runs, the pass rate moves and no code changed. Hash the set,
record it with every run, and refuse to compare two runs whose hashes differ — otherwise you will
eventually chase a "regression" that was a curation change.
</Callout>

## Comparing two runs

The aggregate number tells you *whether* something changed. The per-example diff tells you *what*:

<Run id="prod-eval-5" code={`def compare(before, after):
    ids = sorted(set(before) | set(after))
    improved, regressed, unchanged = [], [], []
    for identifier in ids:
        was, now = before.get(identifier), after.get(identifier)
        if was is None or now is None:
            continue
        if now and not was:
            improved.append(identifier)
        elif was and not now:
            regressed.append(identifier)
        else:
            unchanged.append(identifier)
    return {"improved": improved, "regressed": regressed, "unchanged": unchanged,
            "before_rate": sum(before.values()) / len(before),
            "after_rate": sum(after.values()) / len(after)}

before = {"e1": True, "e2": True, "e3": False, "e4": True, "e5": False, "e6": True}
after  = {"e1": True, "e2": False, "e3": True, "e4": True, "e5": True, "e6": True}

result = compare(before, after)
print(f"pass rate {result['before_rate']:.2f} -> {result['after_rate']:.2f}")
print(f"improved:  {result['improved']}")
print(f"regressed: {result['regressed']}")
print()
print("The rate rose by one example, and one case that used to work now does not.")
print("An aggregate alone would have hidden that entirely.")`} />

A change that fixes three examples and breaks two shows as "+1" on the summary. The regression
list is what stops you shipping it without looking.

## A regression gate

<Run id="prod-eval-7" code={`def gate(previous, current, *, tolerance=0.0, forbid_regressions=True):
    """Return (ok, reasons). Used as a CI check before a prompt change merges."""
    reasons = []
    if current["eval_set_hash"] != previous["eval_set_hash"]:
        reasons.append("the eval set changed — compare like with like before judging")

    before_rate = previous["passed"] / previous["total"]
    after_rate = current["passed"] / current["total"]
    if after_rate < before_rate - tolerance:
        reasons.append(f"pass rate fell from {before_rate:.3f} to {after_rate:.3f}")

    if forbid_regressions and current.get("regressed"):
        reasons.append(f"examples regressed: {current['regressed']}")

    if current["cost_usd"] > previous["cost_usd"] * 1.5:
        reasons.append(f"cost rose from {previous['cost_usd']} to {current['cost_usd']}")

    return not reasons, reasons

previous = {"passed": 27, "total": 30, "cost_usd": 0.15, "eval_set_hash": "abc123"}

for label, current in [
    ("a clean improvement", {"passed": 29, "total": 30, "cost_usd": 0.16,
                             "eval_set_hash": "abc123", "regressed": []}),
    ("better on average, worse somewhere", {"passed": 28, "total": 30, "cost_usd": 0.16,
                                            "eval_set_hash": "abc123", "regressed": ["e7"]}),
    ("much more expensive", {"passed": 29, "total": 30, "cost_usd": 0.40,
                             "eval_set_hash": "abc123", "regressed": []}),
    ("the set moved", {"passed": 30, "total": 33, "cost_usd": 0.16,
                       "eval_set_hash": "def456", "regressed": []}),
]:
    ok, reasons = gate(previous, current)
    print(f"{'PASS' if ok else 'BLOCK'}  {label}")
    for reason in reasons:
        print(f"        {reason}")`} />

<Callout type="warning">
Do not gate on the pass rate alone. A change that improves the average while breaking a case
somebody depends on is still a regression, and cost is a real axis — a prompt that gains two
points and triples the bill is a decision for a person, not a threshold.
</Callout>

## Recap

- Keep the eval set as JSONL: inputs plus the properties an acceptable answer must have. Twenty
  curated examples beat two hundred generated ones.
- Write one grader per property, so a failure names which property broke.
- Run concurrently with a semaphore and report cost alongside the pass rate.
- Record the model, prompt version and hash, retrieval settings and the **eval-set hash** with
  every run.
- Compare per example, not just on the aggregate — improved, regressed, unchanged.
- Split into train, dev and test so prompt tuning does not quietly overfit the set.
