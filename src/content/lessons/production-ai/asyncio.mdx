<Callout type="warning" title="A difference in this page only">
In a script you start the event loop yourself with `asyncio.run(main())`. This page already runs
your code *inside* a loop, so `await` works at the top level and `asyncio.run` does not. Every
other detail is identical, and the listings show the `asyncio.run` form where it belongs.
</Callout>

## Sequential against concurrent

<Run id="prod-async-2" code={`import asyncio, time

async def fake_api_call(prompt, latency=0.05):
    """Stands in for a model call: mostly waiting."""
    await asyncio.sleep(latency)
    return f"reply to {prompt}"

prompts = [f"question {n}" for n in range(10)]

started = time.perf_counter()
sequential = []
for prompt in prompts:
    sequential.append(await fake_api_call(prompt))
sequential_ms = (time.perf_counter() - started) * 1000

started = time.perf_counter()
concurrent = await asyncio.gather(*(fake_api_call(p) for p in prompts))
concurrent_ms = (time.perf_counter() - started) * 1000

print(f"sequential: {sequential_ms:7.1f} ms")
print(f"concurrent: {concurrent_ms:7.1f} ms")
print(f"speed-up:   {sequential_ms / concurrent_ms:7.1f}x")
print()
print("same answers:", sequential == concurrent)`} />

Ten calls that each wait 50 ms take 500 ms in sequence and about 50 ms together. Nothing got
faster — the waiting simply overlapped.

<Callout type="warning">
`await` on its own does **not** create concurrency. `await a(); await b()` runs `a` to completion
before starting `b`, exactly like synchronous code. Concurrency comes from `gather`, `TaskGroup`
or `create_task` — from starting things before awaiting them.
</Callout>

<Run id="prod-async-3" code={`import asyncio, time

async def work(name, seconds):
    await asyncio.sleep(seconds)
    return name

# Sequential, despite every line having an await.
started = time.perf_counter()
first = await work("a", 0.05)
second = await work("b", 0.05)
print(f"awaited in turn:  {(time.perf_counter() - started) * 1000:6.1f} ms")

# Concurrent.
started = time.perf_counter()
both = await asyncio.gather(work("a", 0.05), work("b", 0.05))
print(f"gathered:         {(time.perf_counter() - started) * 1000:6.1f} ms")`} />

## Bounding concurrency

Launching a thousand calls at once will hit a rate limit, exhaust your connection pool, or both.
A semaphore caps how many run at a time:

<Run id="prod-async-4" code={`import asyncio, time

async def fake_api_call(n, latency=0.03):
    await asyncio.sleep(latency)
    return n * 2

async def run_all(items, limit):
    semaphore = asyncio.Semaphore(limit)
    in_flight, peak = 0, 0

    async def guarded(item):
        nonlocal in_flight, peak
        async with semaphore:
            in_flight += 1
            peak = max(peak, in_flight)
            try:
                return await fake_api_call(item)
            finally:
                in_flight -= 1

    results = await asyncio.gather(*(guarded(i) for i in items))
    return results, peak

items = list(range(40))
for limit in [1, 5, 20]:
    started = time.perf_counter()
    results, peak = await run_all(items, limit)
    elapsed = (time.perf_counter() - started) * 1000
    print(f"limit {limit:>3}: {elapsed:7.1f} ms   peak in flight {peak:>3}   results {len(results)}")`} />

The semaphore is the single most important line in a production async client. Without it,
concurrency is whatever the input size happens to be.

<Callout type="ai" title="Why this matters for AI">
Embedding a corpus, running an evaluation set, or answering a batch of questions are all the same
shape: hundreds of independent calls that are almost entirely waiting. Sequentially, a
500-question evaluation at two seconds a call takes seventeen minutes; at a concurrency of twenty
it takes under a minute, and you will actually run it on every change. The semaphore is what keeps
that from turning into a wall of 429s — and note that the right limit comes from the rate limit
and the pool size, not from how many items you have.
</Callout>

## Failures

By default `gather` propagates the first exception and you lose every other result.
`return_exceptions=True` keeps them:

<Run id="prod-async-5" code={`import asyncio

async def flaky(n):
    await asyncio.sleep(0.01)
    if n % 3 == 0:
        raise ValueError(f"item {n} failed")
    return n * 2

# Default: one failure loses everything.
try:
    await asyncio.gather(*(flaky(n) for n in range(6)))
except ValueError as error:
    print("gather raised:", error, "— and the other five results are gone")

print()

outcomes = await asyncio.gather(*(flaky(n) for n in range(6)), return_exceptions=True)
succeeded = [o for o in outcomes if not isinstance(o, Exception)]
failed = [(n, o) for n, o in enumerate(outcomes) if isinstance(o, Exception)]

print(f"succeeded: {succeeded}")
for position, error in failed:
    print(f"failed:    item {position}: {type(error).__name__}: {error}")`} />

For a batch job that is almost always what you want: finish everything, then report what failed.

<Run id="prod-async-6" code={`import asyncio
from dataclasses import dataclass

@dataclass
class Outcome:
    item: object
    value: object = None
    error: Exception | None = None

    @property
    def ok(self):
        return self.error is None

async def run_batch(items, worker, limit=8):
    """Run everything, keep every outcome, never lose a result to one failure."""
    semaphore = asyncio.Semaphore(limit)

    async def guarded(item):
        async with semaphore:
            try:
                return Outcome(item, value=await worker(item))
            except Exception as error:
                return Outcome(item, error=error)

    return await asyncio.gather(*(guarded(i) for i in items))

async def embed(text):
    await asyncio.sleep(0.01)
    if "bad" in text:
        raise ValueError("unembeddable")
    return len(text)

outcomes = await run_batch(["alpha", "bad input", "gamma", "delta", "also bad"], embed)

print(f"{sum(o.ok for o in outcomes)} of {len(outcomes)} succeeded")
for outcome in outcomes:
    print(f"  {'ok  ' if outcome.ok else 'FAIL'} {outcome.item!r:14} {outcome.value or outcome.error}")`} />

## Timeouts

A call that hangs holds a semaphore slot for ever. Bound it:

<Run id="prod-async-7" code={`import asyncio

async def slow(seconds):
    await asyncio.sleep(seconds)
    return "finished"

for budget, duration in [(0.10, 0.02), (0.05, 0.50)]:
    try:
        async with asyncio.timeout(budget):
            result = await slow(duration)
        print(f"budget {budget}s, took {duration}s -> {result}")
    except TimeoutError:
        print(f"budget {budget}s, took {duration}s -> timed out")

print()
# wait_for is the older spelling of the same idea.
try:
    await asyncio.wait_for(slow(0.5), timeout=0.05)
except TimeoutError:
    print("asyncio.wait_for also raises TimeoutError")`} />

## Results as they arrive

`gather` waits for everything. When you want to stream progress, take results as they finish:

<Run id="prod-async-8" code={`import asyncio, random, time

async def work(n):
    await asyncio.sleep(random.Random(n).uniform(0.01, 0.08))
    return n

started = time.perf_counter()
for coroutine in asyncio.as_completed([work(n) for n in range(8)]):
    result = await coroutine
    print(f"  {(time.perf_counter() - started) * 1000:6.1f} ms  finished {result}")`} />

Results arrive out of order, which is the point — a progress bar can move, and a downstream stage
can start on the first result instead of waiting for the slowest.

## Never block the loop

One synchronous call blocks *everything*, because there is only one thread:

<Run id="prod-async-9" code={`import asyncio, time

async def ticker(name, ticks=4):
    for tick in range(ticks):
        await asyncio.sleep(0.02)
        print(f"  {name} tick {tick}")

async def blocking_work():
    time.sleep(0.12)                 # the wrong sleep: blocks the whole loop
    print("  blocking work done")

async def cooperative_work():
    await asyncio.sleep(0.12)        # yields, so other tasks run
    print("  cooperative work done")

print("with a blocking call:")
await asyncio.gather(ticker("tick"), blocking_work())

print()
print("with an awaited call:")
await asyncio.gather(ticker("tick"), cooperative_work())`} />

In the first run every tick is stuck behind the blocking call. The rule: inside `async def`, never
call anything that waits without `await`. If you must — a synchronous SDK, a CPU-heavy function —
push it to a thread:

```python
import asyncio

def parse_huge_file(path):          # synchronous, CPU-heavy
    ...

result = await asyncio.to_thread(parse_huge_file, "corpus.jsonl")
```

## The shape in a real script

```python
import asyncio, anthropic

client = anthropic.AsyncAnthropic()

async def answer(question: str, semaphore: asyncio.Semaphore) -> str:
    async with semaphore:
        async with asyncio.timeout(60):
            response = await client.messages.create(
                model="claude-opus-5",
                max_tokens=1024,
                messages=[{"role": "user", "content": question}],
            )
        return "".join(b.text for b in response.content if b.type == "text")

async def main() -> None:
    semaphore = asyncio.Semaphore(8)
    questions = load_questions()
    outcomes = await asyncio.gather(
        *(answer(q, semaphore) for q in questions),
        return_exceptions=True,
    )
    for question, outcome in zip(questions, outcomes):
        record(question, outcome)

asyncio.run(main())          # the entry point a script needs, and this page does not
```

## Recap

- async helps I/O-bound work — API calls, queries, fetches — and does nothing for CPU-bound work.
- `await` alone is sequential. Concurrency comes from `gather`, `TaskGroup` or `create_task`.
- Bound concurrency with `asyncio.Semaphore`, sized from your rate limit, not your input.
- `gather(..., return_exceptions=True)` keeps every result when one call fails.
- `async with asyncio.timeout(n)` stops a hung call holding a slot; `as_completed` streams results
  as they arrive.
- One blocking call freezes the whole loop. Use `asyncio.to_thread` for synchronous work.
