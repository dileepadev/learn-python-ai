When an answer is wrong, the answer tells you nothing. What tells you something is the record of
what was retrieved, what was sent, what came back and how long each part took.

## Strings you cannot query

<Run id="prod-obs-1" code={`import json, time

question = "How much overlap between chunks?"
latency_ms = 1342
tokens = {"input": 1820, "output": 74}

print("as a string:")
print(f"answered {question!r} in {latency_ms}ms using {tokens['input']}+{tokens['output']} tokens")
print()
print("as an event:")
print(json.dumps({
    "event": "answer",
    "question": question,
    "latency_ms": latency_ms,
    "input_tokens": tokens["input"],
    "output_tokens": tokens["output"],
}))`} />

The first line is readable and useless: "what is the p95 latency for questions over 2,000 input
tokens?" cannot be answered without parsing prose. The second is one field access away.

## A JSON formatter

<Run id="prod-obs-2" code={`import json, logging, sys, time

class JsonFormatter(logging.Formatter):
    """One JSON object per line, with anything passed via extra merged in."""

    RESERVED = set(logging.LogRecord("", 0, "", 0, "", (), None).__dict__) | {
        "message", "asctime", "taskName"
    }

    def format(self, record):
        event = {
            "ts": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime(record.created)),
            "level": record.levelname.lower(),
            "logger": record.name,
            "message": record.getMessage(),
        }
        for key, value in record.__dict__.items():
            if key not in self.RESERVED:
                event[key] = value
        if record.exc_info:
            event["error"] = self.formatException(record.exc_info).splitlines()[-1]
        return json.dumps(event, default=str)

logger = logging.getLogger("rag")
logger.setLevel(logging.INFO)
logger.handlers.clear()
handler = logging.StreamHandler(sys.stdout)
handler.setFormatter(JsonFormatter())
logger.addHandler(handler)
logger.propagate = False

logger.info("retrieved", extra={"request_id": "r-1", "k": 5, "top_score": 0.82})
logger.warning("low confidence", extra={"request_id": "r-1", "top_score": 0.19})

try:
    raise ValueError("embedding dimension mismatch")
except ValueError:
    logger.exception("embedding failed", extra={"request_id": "r-1"})`} />

`extra=` is the whole technique: structured fields travel with the message instead of being
formatted into it.

<Callout type="warning">
`logging` reserves a set of attribute names on every record — `name`, `module`, `args`, `msg` and
others. Passing one of them in `extra` raises `KeyError` at the call site. `request_id`,
`latency_ms` and their kind are safe; `message` and `module` are not.
</Callout>

## One id per request

Without a correlation id, concurrent requests interleave into an unreadable stream:

<Run id="prod-obs-3" code={`import json, uuid

def emit(event, **fields):
    print(json.dumps({"event": event, **fields}))

def handle(question):
    request_id = "r-" + uuid.uuid4().hex[:8]
    emit("request.start", request_id=request_id, question=question)
    emit("retrieval", request_id=request_id, k=5, kept=2, top_score=0.81)
    emit("generation", request_id=request_id, model="claude-opus-5",
         input_tokens=1820, output_tokens=74)
    emit("request.end", request_id=request_id, outcome="answered", latency_ms=1342)
    return request_id

for question in ["how much overlap?", "what dtype?"]:
    handle(question)`} />

Every line carries `request_id`, so one grep reassembles a single request out of a day of traffic.
In an async service the id belongs in a `contextvars.ContextVar`, so it follows the work without
being threaded through every function signature.

## Spans

<Run id="prod-obs-4" code={`import json, time
from contextlib import contextmanager

@contextmanager
def span(name, request_id, **fields):
    """Time a stage and record whether it succeeded — the module 2 pattern, applied."""
    started = time.perf_counter()
    status = "ok"
    try:
        yield fields
    except Exception as error:
        status = "error"
        fields["error"] = f"{type(error).__name__}: {error}"
        raise
    finally:
        print(json.dumps({
            "event": "span",
            "span": name,
            "request_id": request_id,
            "status": status,
            "ms": round((time.perf_counter() - started) * 1000, 2),
            **fields,
        }))

request_id = "r-4f2a"

with span("embed_query", request_id, model="voyage-3"):
    time.sleep(0.01)

with span("retrieve", request_id) as fields:
    time.sleep(0.02)
    fields["candidates"] = 50
    fields["kept"] = 4

try:
    with span("generate", request_id, model="claude-opus-5"):
        time.sleep(0.01)
        raise TimeoutError("upstream took too long")
except TimeoutError:
    pass`} />

The `yield fields` is what lets a stage record what it *found* as well as how long it took — the
candidate count is only known inside the block.

## What to record for an LLM call

<Run id="prod-obs-5" code={`FIELDS = [
    ("request_id", "Correlates every event in one request."),
    ("model", "Which model actually served it. Changes more often than you expect."),
    ("prompt_version / prompt_hash", "Which prompt produced this. Essential for a diff."),
    ("input_tokens / output_tokens", "Cost, and the input growth that signals a context leak."),
    ("cache_read_tokens / cache_write_tokens", "Whether caching is working at all."),
    ("stop_reason", "Distinguishes a finished answer from a truncation or a refusal."),
    ("latency_ms / time_to_first_token_ms", "The two latencies users experience differently."),
    ("retrieved / kept / top_score", "Why the answer had the context it had."),
    ("cited / unsupported", "The citation check from module 7."),
    ("outcome", "answered, refused, no_context, budget, error."),
    ("cost_usd", "Computed at the edge, so it is queryable without a join."),
]

for field, why in FIELDS:
    print(f"{field:<32} {why}")`} />

<Callout type="ai" title="Why this matters for AI">
These systems fail in ways a stack trace never shows: retrieval returned the wrong passages, the
prompt changed last Tuesday, input tokens have tripled since a context-clearing bug, the cache hit
rate quietly went to zero. None of those raise an exception, and none are visible in the answer.
Logging `outcome`, `top_score`, the token counts and the prompt hash turns every one of them into
a query you can run — and a dashboard you can watch before a user complains.
</Callout>

## Redaction

<Run id="prod-obs-6" code={`import json, re

SECRET_KEYS = {"api_key", "authorization", "password", "token", "secret"}
EMAIL = re.compile(r"[\\w.+-]+@[\\w-]+\\.[\\w.]+")
CARD = re.compile(r"\\b(?:\\d[ -]*?){13,16}\\b")
KEYLIKE = re.compile(r"\\bsk-[A-Za-z0-9_-]{8,}\\b")

def scrub(value):
    if isinstance(value, dict):
        return {k: ("[redacted]" if k.lower() in SECRET_KEYS else scrub(v)) for k, v in value.items()}
    if isinstance(value, list):
        return [scrub(v) for v in value]
    if isinstance(value, str):
        value = KEYLIKE.sub("[key]", value)
        value = EMAIL.sub("[email]", value)
        value = CARD.sub("[card]", value)
        return value
    return value

event = {
    "request_id": "r-1",
    "api_key": "sk-ant-abc123def456",
    "user": {"email": "dileepa@example.com", "id": 42},
    "question": "My card 4111 1111 1111 1111 was charged twice, mail me at a@b.com",
    "headers": {"authorization": "Bearer sk-ant-xyz789abc", "accept": "application/json"},
}

print(json.dumps(scrub(event), indent=2))`} />

<Callout type="warning">
Logs are copied to places your application is not: a search index, a vendor's storage, a laptop
during an incident. Redact at the point of emission, not in the pipeline afterwards — and treat
prompts as data that may contain anything a user pasted, because it will.
</Callout>

## Sampling

Logging every token of every prompt is expensive and rarely useful. Log the metadata always, the
bodies rarely — and always when something went wrong:

<Run id="prod-obs-7" code={`import hashlib

def should_log_body(request_id, outcome, rate=0.01):
    """Always on failure; otherwise a deterministic sample by request id."""
    if outcome != "answered":
        return True, "not a clean answer"
    digest = int(hashlib.sha256(request_id.encode()).hexdigest()[:8], 16)
    sampled = (digest % 10_000) < rate * 10_000
    return sampled, "sampled" if sampled else "skipped"

outcomes = ["answered"] * 8 + ["error", "refused"]
logged = 0
for n, outcome in enumerate(outcomes):
    request_id = f"r-{n:04d}"
    decision, why = should_log_body(request_id, outcome, rate=0.25)
    logged += decision
    print(f"{request_id}  {outcome:<9} {'LOG ' if decision else '    '} {why}")

print()
print(f"bodies logged: {logged} of {len(outcomes)}")`} />

Hashing the request id rather than drawing randomly means the decision is stable — the same
request logs the same way if it is retried, and two services in one trace agree about it.

## Recap

- Emit JSON events with `extra=`, not formatted strings — fields are queryable, prose is not.
- Give every request an id and put it on every event; in async code keep it in a `ContextVar`.
- Wrap each stage in a span that records duration, status and what the stage found.
- For an LLM call record the model, prompt hash, token counts, cache reads, `stop_reason`,
  retrieval fields, citation check, outcome and cost.
- Redact secrets and personal data at the point of emission; prompts contain whatever a user
  pasted.
- Always log metadata, sample bodies deterministically by request id, and always keep the body
  when something failed.
