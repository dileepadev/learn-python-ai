The constraints say what the code is *compatible with*. `>=2.7,<3` for Pydantic means "any 2.x
from 2.7", which lets a security fix in without letting a breaking 3.0 in.

<Callout type="tip">
Set an upper bound on anything that has broken you before, and on anything pre-1.0 — where minor
versions routinely break. Bounding everything tightly is the other failure: it makes your package
impossible to install alongside anything else.
</Callout>

## Constraints are not a lock

<Run id="prod-pkg-3" code={`AVAILABLE = {
    "numpy": ["2.0.0", "2.1.0", "2.2.0", "2.3.1"],
    "pydantic": ["2.7.0", "2.8.2", "2.9.1", "3.0.0"],
}

def resolve(constraint_min, constraint_max, versions):
    """What a fresh install picks: the newest version inside the constraint."""
    def key(v):
        return tuple(int(p) for p in v.split("."))
    allowed = [v for v in versions
               if key(v) >= key(constraint_min) and (constraint_max is None or key(v) < key(constraint_max))]
    return allowed[-1] if allowed else None

print("in January:")
print("  numpy>=2.0    ->", resolve("2.0.0", None, ["2.0.0", "2.1.0"]))
print("  pydantic>=2.7 ->", resolve("2.7.0", "3.0.0", ["2.7.0", "2.8.2"]))
print()
print("in June, with no lock file, the same constraints give:")
print("  numpy>=2.0    ->", resolve("2.0.0", None, AVAILABLE["numpy"]))
print("  pydantic>=2.7 ->", resolve("2.7.0", "3.0.0", AVAILABLE["pydantic"]))
print()
print("Same pyproject.toml, different build, and nothing in your repository changed.")`} />

A **lock file** records the resolution: every package, its exact version, and a hash of the
artefact. It is generated, committed, and refreshed deliberately:

```bash
uv lock                     # resolve and write uv.lock
uv sync                     # install exactly what the lock says
uv lock --upgrade-package numpy   # move one dependency on purpose
```

```bash
# The pip equivalent, if you are not using uv:
pip-compile pyproject.toml -o requirements.lock
pip-sync requirements.lock
```

<Callout type="warning">
`pip install -r requirements.txt` with unpinned constraints does **not** reproduce an environment;
it resolves a fresh one. Two people running the same command on the same repository a month apart
can get different versions, and the one whose evaluation dropped will spend a day looking in the
wrong place.
</Callout>

## A reproducible image

```dockerfile
FROM python:3.12-slim AS build
WORKDIR /app

# Copy only what the dependency layer needs, so it caches.
COPY pyproject.toml uv.lock ./
RUN pip install --no-cache-dir uv && uv sync --frozen --no-dev

COPY src/ ./src/
RUN uv pip install --no-deps .

FROM python:3.12-slim
WORKDIR /app
COPY --from=build /app/.venv /app/.venv
COPY --from=build /app/src /app/src
ENV PATH="/app/.venv/bin:$PATH" PYTHONUNBUFFERED=1

RUN useradd --create-home app && chown -R app /app
USER app

EXPOSE 8000
CMD ["uvicorn", "rag_service.api:app", "--host", "0.0.0.0", "--port", "8000"]
```

`--frozen` is the important flag: it fails the build if the lock file disagrees with
`pyproject.toml`, rather than quietly re-resolving. And the key is not in the image — it arrives
as an environment variable at run time, exactly as in module 2.

## Reproducing a result

<Run id="prod-pkg-5" code={`import hashlib, json, platform, sys

        "python": sys.version.split()[0],
        "platform": platform.system().lower(),
        "lock_hash": "sha256:9f2c...",
    },
    "model": {"id": "claude-opus-5", "effort": "high"},
    "prompt": {"version": "answer@3", "hash": "8b1a2c3d4e5f"},
    "data": {"eval_set": "evals/eval.jsonl", "eval_set_hash": file_hash("eval.jsonl")},

<Callout type="ai" title="Why this matters for AI">
Six things move underneath an AI result, and only one of them is your code: the model version, the
prompt, the eval set, the library versions, the random seeds and the retrieval settings. A number
recorded without all six cannot be reproduced or defended — and when quality drops three weeks
later, the manifest is the difference between a diff and an investigation. Write it beside every
result you would ever quote.
</Callout>

    ...

    ...

  hint="Split the specifier on commas, then read the operator off the front of each clause — check the two-character operators before the one-character ones."
  solution={`def parse(version):
    return tuple(int(part) for part in version.split("."))


def satisfies(version, specifier):
    actual = parse(version)
    for clause in specifier.split(","):
        clause = clause.strip()
        for operator in (">=", "<=", "==", ">", "<"):
            if clause.startswith(operator):
                wanted = parse(clause[len(operator):])
                if operator == ">=" and not actual >= wanted:
                    return False
                if operator == "<=" and not actual <= wanted:
                    return False
                if operator == "==" and not actual == wanted:
                    return False
                if operator == ">" and not actual > wanted:
                    return False
                if operator == "<" and not actual < wanted:
                    return False
                break
    return True


def resolve(versions, specifier):
    allowed = [v for v in versions if satisfies(v, specifier)]
    return max(allowed, key=parse) if allowed else None


VERSIONS = ["2.7.0", "2.8.2", "2.9.1", "3.0.0"]
print(resolve(VERSIONS, ">=2.7,<3"))
print(resolve(VERSIONS, ">=3"))
print(resolve(VERSIONS, ">=4"))`}
  tests={`VERSIONS = ["2.7.0", "2.8.2", "2.9.1", "3.0.0"]

assert satisfies("2.8.2", ">=2.7") is True
assert satisfies("2.6.0", ">=2.7") is False
assert satisfies("3.0.0", "<3") is False
assert satisfies("2.9.1", ">=2.7,<3") is True
assert satisfies("3.0.0", ">=2.7,<3") is False, "The upper bound must exclude 3.0.0."
assert satisfies("2.7.0", "==2.7.0") is True
assert satisfies("2.7.1", "==2.7.0") is False

# ">=2.7" must accept 2.7.0 — (2, 7) <= (2, 7, 0).
assert satisfies("2.7.0", ">=2.7") is True, "A two-part bound must not exclude its own .0 release."

# The two-character operators must be checked before the one-character ones.

    "'<=2.7.0' must not be read as '<' followed by '=2.7.0'."
)
assert satisfies("2.8.0", "<=2.7.0") is False

## Recap

- `src/` layout so tests import the installed package; commit the lock file, never the virtual
  environment.
- `pyproject.toml` declares constraints — what you are compatible with. A **lock file** records a
  resolution, with exact versions and hashes.
- `uv lock` / `uv sync --frozen` (or pip-tools) make a build reproduce; `pip install -r` with loose
  constraints does not.
- Build images from the lock with `--frozen`, run as a non-root user, and pass secrets in at run
  time.
- A prompt change is a behaviour change and belongs in the version and the changelog.
- Record git sha, package version, model, prompt hash, eval-set hash, seeds and the lock hash
  beside every result you would quote.
