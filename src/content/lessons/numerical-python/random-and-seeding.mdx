Randomness is everywhere in machine learning: the weights you start from, the order you see
examples in, the split between train and test, the token a model picks. Controlling it is what
separates a result you can defend from one you cannot repeat.

## The Generator API

<Run id="np-rng-1" code={`import numpy as np

rng = np.random.default_rng(42)

print("uniform [0, 1):", rng.random(4).round(4))
print("normal:        ", rng.normal(size=4).round(4))
print("integers:      ", rng.integers(0, 100, size=5))
print("choice:        ", rng.choice(["opus", "sonnet", "haiku"], size=4))
print("permutation:   ", rng.permutation(8))`} />

The seed fixes the entire stream. Two generators made from the same seed produce identical
sequences, for ever:

<Run id="np-rng-2" code={`import numpy as np

a = np.random.default_rng(42)
b = np.random.default_rng(42)
c = np.random.default_rng(7)

print("a:", a.random(3).round(4))
print("b:", b.random(3).round(4), "<- identical")
print("c:", c.random(3).round(4), "<- different seed")

print()
print("a continues:", a.random(3).round(4))
print("b continues:", b.random(3).round(4), "<- still in step")`} />

<Callout type="warning">
`np.random.seed(42)` and `np.random.random()` use one hidden global generator shared by your
code and every library you import. Seeding it makes your run reproducible only until some library
draws from it too, or draws a different number of values than it did last week. Use
`np.random.default_rng(seed)` and pass the generator where it is needed.
</Callout>

## Independent streams

When several parts of a pipeline need randomness, give each its own generator rather than
interleaving draws from one. `spawn` derives children that are statistically independent and
still fully determined by the parent seed:

<Run id="np-rng-3" code={`import numpy as np

parent = np.random.default_rng(42)
shuffle_rng, init_rng, dropout_rng = parent.spawn(3)

print("shuffle:", shuffle_rng.permutation(6))
print("init:   ", init_rng.normal(size=3).round(4))
print("dropout:", dropout_rng.random(4).round(4))

# Reproducible: the same parent seed rebuilds exactly the same children.
again = np.random.default_rng(42).spawn(3)
print()
print("shuffle again:", again[0].permutation(6))`} />

## Shuffling and splitting a dataset

Shuffle **indices**, not the data, so several parallel arrays stay aligned:

<Run id="np-rng-6" code={`import numpy as np

rng = np.random.default_rng(42)

n = 10
features = np.arange(n * 2).reshape(n, 2)
labels = np.array(["a", "b"] * 5)

order = rng.permutation(n)
print("shuffled order:", order)

features, labels = features[order], labels[order]

split = int(0.8 * n)
train_x, test_x = features[:split], features[split:]
train_y, test_y = labels[:split], labels[split:]

print("train:", train_x.shape, list(train_y))
print("test: ", test_x.shape, list(test_y))`} />

<Callout type="ai" title="Why this matters for AI">
A reported score is a claim about a specific split of a specific dataset. If the split is
unseeded, rerunning the same code gives a different number, and comparing two models tells you
about the split as much as the models. Seed the shuffle, record the seed alongside the metric,
and evaluate every candidate on the *same* split. The same applies to weight initialisation and
dropout — anything that differs run to run has to be pinned before a comparison means anything.
</Callout>

## Sampling with a temperature

This is how a language model picks its next token. The logits become probabilities through a
softmax, and temperature controls how sharp that distribution is:

<Run id="np-rng-7" code={`import numpy as np

def softmax(logits, temperature=1.0):
    scaled = logits / temperature
    shifted = scaled - scaled.max()
    exponentiated = np.exp(shifted)
    return exponentiated / exponentiated.sum()

logits = np.array([2.0, 1.0, 0.5, 0.1])
tokens = np.array(["the", "a", "an", "zebra"])

for temperature in (0.1, 0.5, 1.0, 2.0):
    probabilities = softmax(logits, temperature)
    print(f"T={temperature:<4} {probabilities.round(3)}")`} />

Low temperature concentrates the mass on the top token and the output becomes nearly
deterministic; high temperature flattens it and unlikely tokens start appearing.

<Run id="np-rng-8" code={`import numpy as np

def softmax(logits, temperature=1.0):
    scaled = logits / temperature
    shifted = scaled - scaled.max()
    exponentiated = np.exp(shifted)
    return exponentiated / exponentiated.sum()

logits = np.array([2.0, 1.0, 0.5, 0.1])
tokens = np.array(["the", "a", "an", "zebra"])

for temperature in (0.1, 1.0, 2.0):
    rng = np.random.default_rng(0)
    sampled = rng.choice(tokens, size=12, p=softmax(logits, temperature))
    print(f"T={temperature:<4} {' '.join(sampled)}")`} />

Greedy decoding is the limit as temperature approaches zero — just `argmax`, no sampling at all:

<Run id="np-rng-9" code={`import numpy as np

logits = np.array([2.0, 1.0, 0.5, 0.1])
tokens = np.array(["the", "a", "an", "zebra"])

print("greedy:", tokens[logits.argmax()])

# Top-k: keep the k best logits, mask the rest out before sampling.
def top_k(logits, k):
    masked = np.full_like(logits, -np.inf)
    best = np.argpartition(logits, -k)[-k:]
    masked[best] = logits[best]
    return masked

print("top-2 logits:", top_k(logits, 2))

shifted = top_k(logits, 2) - top_k(logits, 2).max()
probabilities = np.exp(shifted) / np.exp(shifted).sum()
print("top-2 probs: ", probabilities.round(3))`} />

Masking with `-inf` works because `np.exp(-inf)` is exactly `0`, so those tokens can never be
drawn.

def sample(logits, temperature, rng):
    scaled = logits / temperature
    shifted = scaled - scaled.max()
    probabilities = np.exp(shifted) / np.exp(shifted).sum()
    return rng.choice(len(logits), p=probabilities)

## Recap

- `np.random.default_rng(seed)` gives a private, seeded generator. Pass it around; do not reach
  for the global `np.random` functions.
- The same seed reproduces the same stream exactly — which is what makes a reported score
  checkable.
- `parent.spawn(n)` derives independent child streams from one seed.
- Shuffle **indices** and apply the same order to every parallel array, so rows keep their
  labels.
- A temperature divides the logits before the softmax: low sharpens towards greedy, high
  flattens. Masking with `-inf` removes a token entirely, because `exp(-inf)` is 0.
