Training a model means repeatedly asking "if I nudge this number, does the loss go up or down,
and by how much?". The answer is a gradient. You will rarely derive one by hand in practice — a
framework does it — but knowing what it *is* turns a training loop from magic into mechanics.

## A derivative is a slope

<Run id="np-grad-1" code={`import numpy as np

def f(x):
    return x ** 2

def numerical_derivative(f, x, eps=1e-6):
    return (f(x + eps) - f(x - eps)) / (2 * eps)

for x in [-2.0, -0.5, 0.0, 1.0, 3.0]:
    print(f"x={x:5.1f}  f(x)={f(x):6.2f}  slope={numerical_derivative(f, x):7.3f}  (exact 2x = {2 * x:5.1f})")`} />

The slope is positive where the curve rises and negative where it falls, and it is zero at the
minimum. That last fact is the whole idea: **step in the opposite direction of the slope and the
value goes down.**

<Run id="np-grad-2" code={`import numpy as np

x = 3.0
learning_rate = 0.2

for step in range(8):
    gradient = 2 * x
    x = x - learning_rate * gradient
    print(f"step {step + 1}: x={x:8.5f}  f(x)={x ** 2:8.5f}")`} />

## Gradients of several variables

With more than one input, the derivative becomes a vector of partial derivatives — one per input,
each answering "if I nudge only this one, what happens?".

<Run id="np-grad-3" code={`import numpy as np

def loss(w):
    # 3*w0^2 + w1^2 + 2*w0*w1
    return 3 * w[0] ** 2 + w[1] ** 2 + 2 * w[0] * w[1]

def analytic_gradient(w):
    return np.array([6 * w[0] + 2 * w[1], 2 * w[1] + 2 * w[0]])

def numerical_gradient(f, w, eps=1e-6):
    gradient = np.zeros_like(w, dtype=float)
    for i in range(w.size):
        step = np.zeros_like(w, dtype=float)
        step[i] = eps
        gradient[i] = (f(w + step) - f(w - step)) / (2 * eps)
    return gradient

w = np.array([1.0, 2.0])
print("loss:      ", loss(w))
print("analytic:  ", analytic_gradient(w))
print("numerical: ", numerical_gradient(loss, w).round(6))`} />

The gradient points in the direction of **steepest increase**, so descent subtracts it:

<Run id="np-grad-4" code={`import numpy as np

def loss(w):
    return 3 * w[0] ** 2 + w[1] ** 2 + 2 * w[0] * w[1]

def gradient(w):
    return np.array([6 * w[0] + 2 * w[1], 2 * w[1] + 2 * w[0]])

w = np.array([1.0, 2.0])
for step in range(6):
    w = w - 0.1 * gradient(w)
    print(f"step {step + 1}: w={w.round(5)}  loss={loss(w):.6f}")`} />

## The chain rule

A pipeline of functions has a gradient that is the product of each stage's gradient. If
`y = g(f(x))`, then `dy/dx = dg/df * df/dx`:

<Run id="np-grad-5" code={`import numpy as np

# Forward: x -> u = 2x + 1 -> y = u^2
def forward(x):
    u = 2 * x + 1
    y = u ** 2
    return u, y

# Backward: dy/du = 2u, du/dx = 2, so dy/dx = 2u * 2
def backward(x):
    u = 2 * x + 1
    dy_du = 2 * u
    du_dx = 2.0
    return dy_du * du_dx

def numerical_derivative(f, x, eps=1e-6):
    return (f(x + eps) - f(x - eps)) / (2 * eps)

x = 3.0
u, y = forward(x)
print(f"x={x}  u={u}  y={y}")
print("chain rule: ", backward(x))
print("numerical:  ", round(numerical_derivative(lambda v: forward(v)[1], x), 6))`} />

<Callout type="ai" title="Why this matters for AI">
Backpropagation is the chain rule applied to a graph. A forward pass records what each layer
computed; the backward pass walks the graph in reverse, multiplying each stage's local gradient
into the gradient flowing back from the loss. Everything a framework's autograd does is this,
bookkept automatically. Two consequences you will meet in practice fall straight out of the
multiplication: many small local gradients multiply towards zero — the vanishing gradient — and
many large ones explode, which is why gradients are clipped.
</Callout>

## The gradient of a squared-error loss

This is the one worth knowing by heart, because it is the loss behind linear regression and the
final layer of countless models.

For predictions `p = X @ w` and targets `y`, with `loss = mean((p - y)^2)`:

- `d loss / d p = 2 * (p - y) / n`
- `d p / d w = X`
- so `d loss / d w = X.T @ (2 * (p - y) / n)`

<Run id="np-grad-6" code={`import numpy as np

rng = np.random.default_rng(0)

n, features = 50, 3
X = rng.normal(size=(n, features))
true_w = np.array([2.0, -1.0, 0.5])
y = X @ true_w + rng.normal(scale=0.1, size=n)

def loss(w):
    predictions = X @ w
    return np.mean((predictions - y) ** 2)

def gradient(w):
    predictions = X @ w
    return X.T @ (2 * (predictions - y) / n)

w = np.zeros(features)
print(f"start: loss={loss(w):.4f}  w={w}")

for step in range(1, 61):
    w = w - 0.1 * gradient(w)
    if step % 15 == 0:
        print(f"step {step:3}: loss={loss(w):.6f}  w={w.round(4)}")

print()
print("recovered:", w.round(3))
print("true:     ", true_w)`} />

That is a complete training loop: forward pass, loss, gradient, update. Everything module 5 adds
is more layers and a smarter optimiser.

## Gradient checking

When you write a gradient by hand, check it against a numerical one. The numerical version is far
too slow to train with — it costs two forward passes per parameter — but it is the ground truth
for a bug hunt:

<Run id="np-grad-7" code={`import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(size=(20, 3))
y = rng.normal(size=20)

def loss(w):
    return np.mean((X @ w - y) ** 2)

def analytic_gradient(w):
    return X.T @ (2 * (X @ w - y) / len(y))

def numerical_gradient(f, w, eps=1e-6):
    gradient = np.zeros_like(w, dtype=float)
    for i in range(w.size):
        step = np.zeros_like(w, dtype=float)
        step[i] = eps
        gradient[i] = (f(w + step) - f(w - step)) / (2 * eps)
    return gradient

w = rng.normal(size=3)
analytic = analytic_gradient(w)
numeric = numerical_gradient(loss, w)

print("analytic: ", analytic.round(8))
print("numerical:", numeric.round(8))
print("max difference:", np.abs(analytic - numeric).max())
print("agree:", np.allclose(analytic, numeric, atol=1e-5))`} />

And here is what a wrong gradient looks like, so you know the failure when you see it:

<Run id="np-grad-8" code={`import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(size=(20, 3))
y = rng.normal(size=20)

def loss(w):
    return np.mean((X @ w - y) ** 2)

def buggy_gradient(w):
    return X.T @ (X @ w - y) / len(y)          # forgot the factor of 2

def numerical_gradient(f, w, eps=1e-6):
    gradient = np.zeros_like(w, dtype=float)
    for i in range(w.size):
        step = np.zeros_like(w, dtype=float)
        step[i] = eps
        gradient[i] = (f(w + step) - f(w - step)) / (2 * eps)
    return gradient

w = rng.normal(size=3)
print("buggy:    ", buggy_gradient(w).round(6))
print("numerical:", numerical_gradient(loss, w).round(6))
print("ratio:    ", (numerical_gradient(loss, w) / buggy_gradient(w)).round(4))`} />

A constant ratio of exactly 2 is the signature of a missing factor. A gradient that is wrong by a
constant still trains — just at the wrong learning rate — which is why this class of bug survives
so long.

<Callout type="warning">
Choose `eps` carefully. Too large and the estimate is inaccurate; too small and floating-point
cancellation destroys it. Around `1e-6` on float64 is the usual sweet spot, and the two-sided
formula above is far more accurate than the one-sided version.
</Callout>

## Recap

- A derivative is a slope: positive going up, negative going down, zero at a minimum.
- A gradient is the vector of partial derivatives, pointing towards steepest **increase** — so
  descent subtracts it, scaled by a learning rate.
- The chain rule multiplies each stage's local gradient; backpropagation is that applied to a
  graph, and it explains both vanishing and exploding gradients.
- For `loss = mean((X @ w - y) ** 2)`, the gradient is `X.T @ (2 * (X @ w - y) / n)`.
- Check a hand-written gradient against a two-sided numerical estimate with `eps` around `1e-6`.
  A constant ratio means a missing factor, which trains anyway and hides for months.
