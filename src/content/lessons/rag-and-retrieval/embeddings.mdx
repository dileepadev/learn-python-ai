<Callout type="warning" title="What runs here">
A real embedding model is an API call, and this sandbox has no network. The lessons in this module
use a **TF-IDF vectoriser** from scikit-learn as a stand-in: it produces genuine, deterministic
vectors with the same shape and the same geometry, so every mechanic you learn — normalising,
cosine similarity, top-k, indexing, hybrid search, re-ranking — is exactly what you will write
against a real model. The one difference is what the vectors *mean*: TF-IDF captures shared words,
where a trained embedding model captures shared meaning. Where that difference matters, the text
says so.
</Callout>

## What an embedding is

A function from text to a fixed-length vector of floats, trained so that texts with similar
meaning land close together.

<Run id="rag-emb-1" code={`import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer

CORPUS = [
    "Retrieval augmented generation grounds answers in your own documents.",
    "RAG systems fetch relevant passages before generating an answer.",
    "Use 10 to 20 percent chunk overlap so sentences are not cut in half.",
    "Store embeddings as float32 to halve the memory they need.",
    "The cat sat on the mat in the afternoon sunshine.",
]

vectoriser = TfidfVectorizer().fit(CORPUS)
vectors = vectoriser.transform(CORPUS).toarray().astype(np.float32)

print("documents:", vectors.shape[0])
print("dimensions:", vectors.shape[1])
print("dtype:     ", vectors.dtype)
print()
print("first vector, first 12 dimensions:")
print(vectors[0][:12].round(3))
print("non-zero dimensions:", int((vectors[0] != 0).sum()), "of", vectors.shape[1])`} />

Every document becomes a point in the same space. Nothing about a single vector is interpretable —
dimension 7 means nothing on its own. What means something is **distance between vectors**.

## Cosine similarity

Module 3 built this: normalise, then take the dot product.

<Run id="rag-emb-2" code={`import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer

CORPUS = [
    "Retrieval augmented generation grounds answers in your own documents.",
    "RAG systems fetch relevant passages before generating an answer.",
    "Use 10 to 20 percent chunk overlap so sentences are not cut in half.",
    "Store embeddings as float32 to halve the memory they need.",
    "The cat sat on the mat in the afternoon sunshine.",
]

vectoriser = TfidfVectorizer().fit(CORPUS)

def embed(texts):
    """Stand-in for an embedding model: text in, unit vectors out."""
    vectors = vectoriser.transform(texts).toarray().astype(np.float32)
    norms = np.linalg.norm(vectors, axis=1, keepdims=True)
    return vectors / np.maximum(norms, 1e-12)

vectors = embed(CORPUS)
print("every row has length:", np.linalg.norm(vectors, axis=1).round(6))
print()

similarity = vectors @ vectors.T          # unit vectors, so the dot product is the cosine
print("pairwise similarity:")
print(similarity.round(3))`} />

Read the diagonal — every document is identical to itself at 1.0 — and then look at the
off-diagonal entries. The two RAG sentences share vocabulary and score highest; the cat is
orthogonal to everything.

<Callout type="tip">
Normalise once, at index time, and every later query is a plain dot product. That is not an
optimisation detail — it is why production vector databases store unit vectors and advertise
"inner product" as their metric.
</Callout>

## Ranking against a query

<Run id="rag-emb-3" code={`import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer

CORPUS = [
    "Retrieval augmented generation grounds answers in your own documents.",
    "RAG systems fetch relevant passages before generating an answer.",
    "Use 10 to 20 percent chunk overlap so sentences are not cut in half.",
    "Store embeddings as float32 to halve the memory they need.",
    "The cat sat on the mat in the afternoon sunshine.",
]

vectoriser = TfidfVectorizer().fit(CORPUS)

def embed(texts):
    vectors = vectoriser.transform(texts).toarray().astype(np.float32)
    return vectors / np.maximum(np.linalg.norm(vectors, axis=1, keepdims=True), 1e-12)

index = embed(CORPUS)

def search(query, k=3):
    scores = index @ embed([query])[0]
    best = np.argpartition(scores, -k)[-k:]
    best = best[np.argsort(scores[best])[::-1]]
    return [(int(i), float(scores[i]), CORPUS[i]) for i in best]

for query in ["how much overlap when chunking?", "how should I store vectors?"]:
    print(f"query: {query}")
    for rank, (index_, score, text) in enumerate(search(query), start=1):
        print(f"  {rank}. {score:.3f}  {text[:64]}")
    print()`} />

That is a search engine: one matrix-vector product and an `argpartition`, exactly the top-k
pattern from module 3.

<Callout type="warning">
Notice the second result of each query scoring well below the first, and the third barely scoring
at all. Retrieval always returns *k* things, however irrelevant — a similarity floor is what stops
a nonsense passage being handed to the model as context. That threshold is a real tuning decision,
not a detail.
</Callout>

## The real call

With a hosted embedding model the shape is the same; only `embed` changes:

```python
# An embedding model is a separate service from the chat model. Anthropic
# recommends a dedicated provider such as Voyage AI; the shape below is
# typical of all of them.
def embed(texts: list[str]) -> np.ndarray:
    response = embeddings_client.embed(
        model="voyage-3",
        input=texts,             # a batch, not one string at a time
        input_type="document",   # or "query" — many models distinguish the two
    )
    vectors = np.array([item.embedding for item in response.data], dtype=np.float32)
    return vectors / np.linalg.norm(vectors, axis=1, keepdims=True)
```

Two details worth carrying over:

- **Batch.** One request with 128 texts is far cheaper and faster than 128 requests. Reach for
  `itertools.batched` from module 2.
- **Ask for the right `input_type`.** Several models embed a question and a passage differently,
  because a question is not a shorter version of its answer.

<Run id="rag-emb-4" code={`from itertools import batched

requests = 0
for group in batched(documents, 128):
    requests += 1          # one API call per batch

print(f"{len(documents)} documents")
print(f"{requests} requests batched, against {len(documents)} unbatched")
print(f"{len(documents) / requests:.0f}x fewer round trips")`} />

## Caching

Embedding the same text twice is money spent on an answer you already had. Key a cache by a hash
of the content, exactly as in module 2:

<Run id="rag-emb-5" code={`import hashlib
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer

CORPUS = ["alpha beta gamma", "beta gamma delta", "gamma delta epsilon"]
vectoriser = TfidfVectorizer().fit(CORPUS)

class EmbeddingCache:
    def __init__(self, model):
        self.model = model
        self.store = {}
        self.computed = 0
        self.reused = 0

    def key(self, text):
        return hashlib.sha256(f"{self.model}\\u0000{text}".encode("utf-8")).hexdigest()[:16]

    def embed(self, texts):
        missing = [t for t in texts if self.key(t) not in self.store]
        if missing:
            fresh = vectoriser.transform(missing).toarray().astype(np.float32)
            fresh /= np.maximum(np.linalg.norm(fresh, axis=1, keepdims=True), 1e-12)
            for text, vector in zip(missing, fresh):
                self.store[self.key(text)] = vector
            self.computed += len(missing)
        self.reused += len(texts) - len(missing)
        return np.stack([self.store[self.key(t)] for t in texts])

cache = EmbeddingCache("tfidf-demo")

cache.embed(CORPUS)
cache.embed(CORPUS)                       # the same corpus again
cache.embed(CORPUS + ["delta epsilon zeta"])

print("computed:", cache.computed)
print("reused:  ", cache.reused)
print("stored:  ", len(cache.store))`} />

Note the model name in the cache key. That is not decoration.

## You cannot mix models

Two models' vectors live in unrelated spaces. Comparing them produces a number, and the number is
meaningless:

<Run id="rag-emb-6" code={`import numpy as np

rng = np.random.default_rng(0)

def fake_model(seed, text, dimensions=256):
    """Two 'models': same text, same dimension, different learned space."""
    local = np.random.default_rng(abs(hash(text)) % (2**31) + seed)
    vector = local.normal(size=dimensions)
    return vector / np.linalg.norm(vector)

text = "retrieval augmented generation"
a = fake_model(0, text)
b = fake_model(1, text)

print("same text, model A vs model B:", round(float(a @ b), 4))
print("same text, model A vs model A:", round(float(a @ fake_model(0, text)), 4))
print()
print("A similarity near zero for identical text means the comparison is nonsense.")`} />

<Callout type="ai" title="Why this matters for AI">
This is the migration trap that catches real systems. Changing embedding model — or even a minor
version of one — invalidates **every vector in your index**, and nothing errors: queries keep
returning k results, they are simply the wrong ones, and quality degrades in a way that looks like
a prompt problem. Store the model id and dimension alongside every vector, refuse to query when
they disagree, and treat a model change as a full re-index.
</Callout>

<Run id="rag-emb-7" code={`import numpy as np

class Index:
    """An index that refuses to answer a query it cannot answer honestly."""

    def __init__(self, model, dimensions):
        self.model = model
        self.dimensions = dimensions
        self.vectors = np.zeros((0, dimensions), dtype=np.float32)

    def add(self, vectors, model, dimensions):
        if model != self.model:
            raise ValueError(f"index was built with {self.model!r}, not {model!r}")
        if dimensions != self.dimensions:
            raise ValueError(f"index is {self.dimensions}-dimensional, not {dimensions}")
        self.vectors = np.vstack([self.vectors, vectors])

    def search(self, vector, model):
        if model != self.model:
            raise ValueError(f"query embedded with {model!r}, index built with {self.model!r}")
        return self.vectors @ vector

index = Index("voyage-3", 8)
index.add(np.ones((3, 8), dtype=np.float32) / np.sqrt(8), "voyage-3", 8)
print("added; index holds", index.vectors.shape)

for model, dimensions in [("voyage-3", 16), ("some-other-model", 8)]:
    try:
        index.add(np.ones((1, dimensions), dtype=np.float32), model, dimensions)
    except ValueError as error:
        print("refused:", error)`} />

## Recap

- An embedding maps text to a fixed-length vector; only distances between vectors mean anything.
- Normalise at index time, then similarity is a dot product and top-k is `argpartition`.
- Batch embedding calls and cache them by a hash of the content **plus the model id**.
- Ask for the right `input_type` when a model distinguishes queries from documents.
- Two models' vectors are incomparable. Store the model and dimension with the index and refuse a
  mismatch, because nothing else will tell you.
- Retrieval always returns k results; a similarity floor is what stops irrelevant context reaching
  the model.
