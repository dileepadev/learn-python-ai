Dense retrieval is good at meaning and bad at literals. Keyword search is the reverse. Production
retrieval runs both, because real queries contain both.

## What dense retrieval misses

Keyword search handles every one of those, because a rare token is exactly what an inverted index
is good at — and fails at the thing dense retrieval does best: finding the passage that answers
the question in different words.

## BM25

BM25 scores a document by how often the query's terms appear in it, weighted by how rare each term
is across the corpus, and adjusted so long documents do not win by length alone.

<Run id="rag-hybrid-2" code={`import math
from collections import Counter

CORPUS = [
    "Retrieval augmented generation grounds answers in your own documents.",
    "Use 10 to 20 percent chunk overlap so sentences are not cut in half.",
    "Error E4021 means the embedding model returned a dimension mismatch.",
    "Store embeddings as float32 to halve the memory they need.",
    "The chunking guide explains overlap, separators and heading paths.",
]

def tokenise(text):
    return [word.strip(".,:;!?()").lower() for word in text.split() if word.strip(".,:;!?()")]

class BM25:
    def __init__(self, documents, k1=1.5, b=0.75):
        self.k1, self.b = k1, b
        self.documents = [tokenise(d) for d in documents]
        self.lengths = [len(d) for d in self.documents]
        self.average_length = sum(self.lengths) / len(self.lengths)
        self.frequencies = [Counter(d) for d in self.documents]

        self.document_frequency = Counter()
        for document in self.documents:
            for term in set(document):
                self.document_frequency[term] += 1
        self.count = len(self.documents)

    def idf(self, term):
        seen_in = self.document_frequency.get(term, 0)
        return math.log(1 + (self.count - seen_in + 0.5) / (seen_in + 0.5))

    def score(self, query, position):
        total = 0.0
        frequencies, length = self.frequencies[position], self.lengths[position]
        for term in tokenise(query):
            if term not in frequencies:
                continue
            occurrences = frequencies[term]
            numerator = occurrences * (self.k1 + 1)
            denominator = occurrences + self.k1 * (1 - self.b + self.b * length / self.average_length)
            total += self.idf(term) * numerator / denominator
        return total

    def search(self, query, k=3):
        scored = [(i, self.score(query, i)) for i in range(self.count)]
        scored.sort(key=lambda pair: pair[1], reverse=True)
        return [(i, round(s, 4)) for i, s in scored[:k] if s > 0]

bm25 = BM25(CORPUS)
for query in ["error E4021", "how much overlap between chunks"]:
    print(f"query: {query}")
    for position, score in bm25.search(query):
        print(f"  {score:7.4f}  {CORPUS[position][:62]}")
    print()`} />

The three parts are worth naming:

- **IDF** — a term appearing in one document out of a million is worth far more than "the".
- **`k1`** saturates term frequency: the tenth occurrence of a word adds much less than the second.
- **`b`** normalises by length, so a long document does not score highly merely for being long.

## Where each one wins

<Run id="rag-hybrid-3" code={`import math
import numpy as np
from collections import Counter
from sklearn.feature_extraction.text import TfidfVectorizer

CORPUS = [
    "Retrieval augmented generation grounds answers in your own documents.",
    "Use 10 to 20 percent chunk overlap so sentences are not cut in half.",
    "Error E4021 means the embedding model returned a dimension mismatch.",
    "Store embeddings as float32 to halve the memory they need.",
    "The chunking guide explains overlap, separators and heading paths.",
    "Splitting text into pieces that share a few words at each boundary.",
]

def tokenise(text):
    return [w.strip(".,:;!?()").lower() for w in text.split() if w.strip(".,:;!?()")]

# Dense side: TF-IDF vectors standing in for an embedding model.
vectoriser = TfidfVectorizer().fit(CORPUS)
def embed(texts):
    vectors = vectoriser.transform(texts).toarray().astype(np.float32)
    return vectors / np.maximum(np.linalg.norm(vectors, axis=1, keepdims=True), 1e-12)
index = embed(CORPUS)

def dense_search(query, k=3):
    scores = index @ embed([query])[0]
    order = np.argsort(scores)[::-1][:k]
    return [(int(i), round(float(scores[i]), 4)) for i in order]

# Keyword side.
class BM25:
    def __init__(self, documents, k1=1.5, b=0.75):
        self.k1, self.b = k1, b
        self.documents = [tokenise(d) for d in documents]
        self.lengths = [len(d) for d in self.documents]
        self.average_length = sum(self.lengths) / len(self.lengths)
        self.frequencies = [Counter(d) for d in self.documents]
        self.document_frequency = Counter()
        for document in self.documents:
            for term in set(document):
                self.document_frequency[term] += 1
        self.count = len(self.documents)

    def score(self, query, position):
        total = 0.0
        frequencies, length = self.frequencies[position], self.lengths[position]
        for term in tokenise(query):
            if term not in frequencies:
                continue
            seen_in = self.document_frequency[term]
            idf = math.log(1 + (self.count - seen_in + 0.5) / (seen_in + 0.5))
            occurrences = frequencies[term]
            total += idf * occurrences * (self.k1 + 1) / (
                occurrences + self.k1 * (1 - self.b + self.b * length / self.average_length))
        return total

    def search(self, query, k=3):
        scored = sorted(((i, self.score(query, i)) for i in range(self.count)),
                        key=lambda p: p[1], reverse=True)
        return [(i, round(s, 4)) for i, s in scored[:k]]

bm25 = BM25(CORPUS)

for query in ["E4021", "how do I break a document into pieces"]:
    print(f"query: {query!r}")
    print("  dense: ", [(i, s) for i, s in dense_search(query)])
    print("  bm25:  ", [(i, s) for i, s in bm25.search(query)])
    print(f"  dense top: {CORPUS[dense_search(query)[0][0]][:60]}")
    print(f"  bm25 top:  {CORPUS[bm25.search(query)[0][0]][:60]}")
    print()`} />

The first query is a bare identifier: BM25 finds it because `E4021` is rare, and the dense side has
almost nothing to work with. The second is a paraphrase sharing barely a word with its answer —
where dense retrieval is supposed to shine, and where a lexical method struggles.

<Callout type="warning">
Our dense stand-in is TF-IDF, which is itself lexical, so it cannot really demonstrate the
paraphrase win. With a trained embedding model, "how do I break a document into pieces" retrieves
the chunking passage comfortably. Take the *shape* of the argument from this lesson and measure
the magnitude on your own corpus.
</Callout>

## Reciprocal rank fusion

The problem with combining two retrievers is that their scores are not comparable — a cosine
similarity of 0.82 and a BM25 score of 7.3 mean nothing to each other. RRF sidesteps that
entirely by using only the **ranks**:

<Run id="rag-hybrid-4" code={`def reciprocal_rank_fusion(rankings, k=60):
    """rankings: a list of ranked id lists, best first. Higher output is better."""
    scores = {}
    for ranking in rankings:
        for rank, identifier in enumerate(ranking, start=1):
            scores[identifier] = scores.get(identifier, 0.0) + 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda pair: pair[1], reverse=True)

dense_ranking = ["c3", "c1", "c7", "c2"]
keyword_ranking = ["c7", "c9", "c1", "c4"]

print(f"{'id':>5} {'fused':>10}  appears in")
for identifier, score in reciprocal_rank_fusion([dense_ranking, keyword_ranking]):
    where = []
    if identifier in dense_ranking:
        where.append(f"dense#{dense_ranking.index(identifier) + 1}")
    if identifier in keyword_ranking:
        where.append(f"keyword#{keyword_ranking.index(identifier) + 1}")
    print(f"{identifier:>5} {score:>10.5f}  {', '.join(where)}")`} />

`c7` wins: third for the dense retriever, first for the keyword one, and the only document both
rate highly. That is exactly the behaviour you want — agreement between two different methods is
strong evidence.

The constant `k` controls how much a top rank dominates:

<Run id="rag-hybrid-5" code={`def rrf_scores(rankings, k):
    scores = {}
    for ranking in rankings:
        for rank, identifier in enumerate(ranking, start=1):
            scores[identifier] = scores.get(identifier, 0.0) + 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda p: p[1], reverse=True)

dense = ["a", "b", "c"]
keyword = ["c", "b", "a"]

for k in [1, 10, 60, 200]:
    order = [identifier for identifier, _ in rrf_scores([dense, keyword], k)]
    print(f"k={k:>3}  {order}")

print()
print("Small k lets a single first place dominate; large k flattens towards consensus.")
print("60 is the conventional default and rarely needs tuning.")`} />

## Weighted score fusion

If you do want to combine scores, normalise each retriever's scores into a comparable range first:

<Run id="rag-hybrid-6" code={`import numpy as np

def min_max(scores):
    values = np.asarray(list(scores.values()), dtype=float)
    low, high = values.min(), values.max()
    if high - low < 1e-12:
        return {key: 0.0 for key in scores}
    return {key: (value - low) / (high - low) for key, value in scores.items()}

dense_scores = {"c1": 0.81, "c3": 0.88, "c7": 0.79, "c2": 0.52}
keyword_scores = {"c7": 7.3, "c9": 5.1, "c1": 4.4, "c4": 1.2}

dense_normalised = min_max(dense_scores)
keyword_normalised = min_max(keyword_scores)

alpha = 0.6      # weight on the dense side
everything = set(dense_normalised) | set(keyword_normalised)

fused = {
    identifier: alpha * dense_normalised.get(identifier, 0.0)
                + (1 - alpha) * keyword_normalised.get(identifier, 0.0)
    for identifier in everything
}

for identifier, score in sorted(fused.items(), key=lambda p: p[1], reverse=True):
    print(f"{identifier:>5} {score:.4f}   dense {dense_normalised.get(identifier, 0):.2f}  "
          f"keyword {keyword_normalised.get(identifier, 0):.2f}")`} />

<Callout type="warning">
Min-max normalisation is computed **per query**, over that query's candidate set, so the same
document scores differently depending on what it was ranked against. It also has no floor: the
worst candidate is always 0.0, even when it is excellent. RRF has neither problem, which is why it
is the default recommendation.
</Callout>

<Callout type="ai" title="Why this matters for AI">
Almost every RAG system that works in production is hybrid, and the reason is the query
distribution rather than any theoretical argument. Users paste error codes, order numbers, config
keys and exact product names — the literals dense retrieval is worst at — and then ask
conversational follow-ups that only a semantic method can answer. Running both and fusing with RRF
costs one extra index and about ten lines, and it removes an entire class of "why can't it find
the thing I literally pasted" complaints.
</Callout>

## Recap

- Dense retrieval fails systematically on identifiers, rare names, versions, numbers and negation.
  Keyword search fails on paraphrase. Real queries contain both.
- BM25 weights terms by rarity (IDF), saturates repeated terms (`k1`) and normalises for document
  length (`b`).
- Fuse with **reciprocal rank fusion**: sum `1/(k + rank)` across rankings, `k = 60`. It needs no
  comparable scales and no tuning.
- Weighted score fusion works but needs per-query normalisation, which is query-dependent and has
  no sensible floor.
- Hybrid costs one extra index and about ten lines, and removes a whole class of failure.
