A vector index is an array of unit vectors, a parallel list of metadata, and a dot product. Start
there — a great many production systems never need more.

## Exact search

<Run id="rag-index-1" code={`import numpy as np, time

rng = np.random.default_rng(0)

for count in [1_000, 10_000, 100_000]:
    index = rng.normal(size=(count, 768)).astype(np.float32)
    index /= np.linalg.norm(index, axis=1, keepdims=True)
    query = index[0]

    started = time.perf_counter()
    scores = index @ query
    best = np.argpartition(scores, -10)[-10:]
    elapsed = (time.perf_counter() - started) * 1000

    print(f"{count:>8,} vectors  {index.nbytes / 1e6:7.1f} MB  {elapsed:7.1f} ms")`} />

A hundred thousand 768-dimension vectors is about 300 MB and searches in a few tens of
milliseconds. That is a perfectly good production system for most internal corpora, and it has no
recall loss, no index build step and no extra service to operate.

## The index

<Run id="rag-index-2" code={`import numpy as np
from dataclasses import dataclass, field

@dataclass
class Record:
    chunk_id: str
    doc_id: str
    text: str
    metadata: dict = field(default_factory=dict)

class VectorIndex:
    """Exact search over unit vectors, with parallel metadata."""

    def __init__(self, model, dimensions):
        self.model = model
        self.dimensions = dimensions
        self.vectors = np.zeros((0, dimensions), dtype=np.float32)
        self.records: list[Record] = []
        self.positions: dict[str, int] = {}

    def __len__(self):
        return len(self.records)

    def add(self, vectors, records):
        vectors = np.asarray(vectors, dtype=np.float32)
        if vectors.shape[1] != self.dimensions:
            raise ValueError(f"expected {self.dimensions} dimensions, got {vectors.shape[1]}")
        if len(vectors) != len(records):
            raise ValueError("one vector per record, please")

        vectors = vectors / np.maximum(np.linalg.norm(vectors, axis=1, keepdims=True), 1e-12)
        for offset, record in enumerate(records):
            self.positions[record.chunk_id] = len(self.records) + offset
        self.vectors = np.vstack([self.vectors, vectors])
        self.records.extend(records)

    def search(self, query_vector, k=5, minimum=0.0):
        if len(self) == 0:
            return []
        query_vector = np.asarray(query_vector, dtype=np.float32)
        query_vector = query_vector / max(float(np.linalg.norm(query_vector)), 1e-12)

        scores = self.vectors @ query_vector
        k = min(k, len(scores))
        best = np.argpartition(scores, -k)[-k:]
        best = best[np.argsort(scores[best])[::-1]]
        return [(self.records[i], float(scores[i])) for i in best if scores[i] >= minimum]

rng = np.random.default_rng(0)
index = VectorIndex("demo", 8)
index.add(
    rng.normal(size=(5, 8)),
    [Record(f"c{i}", "guide", f"chunk number {i}", {"lang": "en"}) for i in range(5)],
)

print("records:", len(index))
for record, score in index.search(index.vectors[2], k=3):
    print(f"  {record.chunk_id} {score:.3f}  {record.text}")`} />

The `minimum` argument is the similarity floor from the last lesson, and it is the difference
between "here are five passages" and "here are the passages that are actually about this".

## Filtering by metadata

Real queries are rarely "search everything". They are "search this customer's documents, in
English, published this year".

<Run id="rag-index-3" code={`import numpy as np

rng = np.random.default_rng(0)
n = 2000
vectors = rng.normal(size=(n, 32)).astype(np.float32)
vectors /= np.linalg.norm(vectors, axis=1, keepdims=True)
metadata = [{"lang": "en" if i % 3 else "si", "year": 2024 + (i % 3)} for i in range(n)]
query = vectors[7]

def post_filter(k=5):
    """Search everything, then throw away what does not match."""
    scores = vectors @ query
    order = np.argsort(scores)[::-1]
    kept = [i for i in order if metadata[i]["lang"] == "si"][:k]
    return [(int(i), float(scores[i])) for i in kept]

def pre_filter(k=5):
    """Narrow first, then search only the candidates."""
    allowed = np.array([i for i, m in enumerate(metadata) if m["lang"] == "si"])
    scores = vectors[allowed] @ query
    k = min(k, len(scores))
    best = np.argpartition(scores, -k)[-k:]
    best = best[np.argsort(scores[best])[::-1]]
    return [(int(allowed[i]), float(scores[i])) for i in best]

print("post-filter:", [i for i, _ in post_filter()])
print("pre-filter: ", [i for i, _ in pre_filter()])
print()
print("candidates searched:")
print(f"  post-filter {n}")
print(f"  pre-filter  {sum(1 for m in metadata if m['lang'] == 'si')}")`} />

Both return the same answers here, because exact search ranks everything anyway. The difference
matters the moment you move to approximate search:

<Callout type="warning">
Post-filtering an **approximate** index is a trap. You ask for the 10 nearest neighbours, then
keep the ones matching your filter — and if none of the 10 match, you get nothing back, even
though excellent matches exist just outside the retrieved set. With a selective filter this fails
almost always. Filter first, or use an index that supports filtered search natively.
</Callout>

## Persisting it

Vectors go in a binary file; metadata goes in JSONL. Both are boring, which is the point:

<Run id="rag-index-4" code={`import json
import numpy as np
from pathlib import Path

rng = np.random.default_rng(0)
vectors = rng.normal(size=(4, 8)).astype(np.float32)
vectors /= np.linalg.norm(vectors, axis=1, keepdims=True)
records = [{"chunk_id": f"c{i}", "doc_id": "guide", "text": f"chunk {i}"} for i in range(4)]

def save(directory, model, vectors, records):
    path = Path(directory)

    np.save(path / "vectors.npy", vectors)
    with open(path / "records.jsonl", "w", encoding="utf-8") as handle:

## Updates and deletes

The naive delete — removing a row from the array — invalidates every position after it. A
tombstone keeps positions stable:

<Run id="rag-index-5" code={`import numpy as np

class TombstoneIndex:
    def __init__(self, dimensions):
        self.vectors = np.zeros((0, dimensions), dtype=np.float32)
        self.ids = []
        self.alive = np.zeros(0, dtype=bool)

    def add(self, vectors, ids):
        self.vectors = np.vstack([self.vectors, np.asarray(vectors, dtype=np.float32)])
        self.ids.extend(ids)
        self.alive = np.concatenate([self.alive, np.ones(len(ids), dtype=bool)])

    def delete(self, chunk_id):
        for position, existing in enumerate(self.ids):
            if existing == chunk_id and self.alive[position]:
                self.alive[position] = False
                return True
        return False

    def search(self, query, k=3):
        scores = np.where(self.alive, self.vectors @ query, -np.inf)
        k = min(k, int(self.alive.sum()))
        if k == 0:
            return []
        best = np.argpartition(scores, -k)[-k:]
        best = best[np.argsort(scores[best])[::-1]]
        return [(self.ids[i], round(float(scores[i]), 3)) for i in best]

    def compact(self):
        """Rebuild without the dead rows. Do this offline, not per request."""
        self.vectors = self.vectors[self.alive]
        self.ids = [i for i, keep in zip(self.ids, self.alive) if keep]
        self.alive = np.ones(len(self.ids), dtype=bool)

rng = np.random.default_rng(0)
index = TombstoneIndex(4)
vectors = rng.normal(size=(5, 4)).astype(np.float32)
vectors /= np.linalg.norm(vectors, axis=1, keepdims=True)
index.add(vectors, [f"c{i}" for i in range(5)])

query = vectors[1]
print("before delete:", index.search(query))
index.delete("c1")
print("after delete: ", index.search(query))
print("rows stored:", len(index.ids), "alive:", int(index.alive.sum()))
index.compact()
print("after compact:", len(index.ids))`} />

Masking with `-inf` rather than filtering keeps the index a single contiguous array, which is what
makes the search fast.

## When brute force is not enough

<Run id="rag-index-6" code={`import numpy as np

def brute_force_estimate(count, dimensions=768, gflops=20.0):
    """One query is count x dimensions multiply-adds."""
    operations = 2 * count * dimensions
    return operations / (gflops * 1e9) * 1000     # milliseconds

print(f"{'vectors':>13} {'memory':>10} {'per query':>12}")
for count in [10_000, 100_000, 1_000_000, 10_000_000, 100_000_000]:
    memory = count * 768 * 4 / 1e9
    print(f"{count:>13,} {memory:>9.1f} GB {brute_force_estimate(count):>10.1f} ms")

print()
print("Rules of thumb:")
for rule in [
    "Under ~100k vectors: NumPy in process. No index, no service, exact results.",
    "100k to a few million: still viable, but consider sharding or a library index.",
    "Beyond that: approximate search, and a dedicated store.",
    "Any scale, if you need durability, concurrency and filtering: a real database.",
]:
    print("  -", rule)`} />

<Callout type="ai" title="Why this matters for AI">
The instinct to reach for a vector database on day one costs weeks and usually buys nothing. Most
internal corpora — a documentation site, a support archive, a code base — are tens of thousands of
chunks, which is a 100 MB array and a millisecond query. Start with NumPy and a JSONL file, get
the chunking and the evaluation right, and move to a real store when *scale* forces it rather than
when the architecture diagram suggests it. The retrieval quality work transfers; the infrastructure
work does not.
</Callout>

## What approximate search trades

<Run id="rag-index-7" code={`import numpy as np

rng = np.random.default_rng(0)
n, dimensions = 20_000, 64
vectors = rng.normal(size=(n, dimensions)).astype(np.float32)
vectors /= np.linalg.norm(vectors, axis=1, keepdims=True)

# A crude IVF: cluster into buckets, search only the nearest few buckets.
buckets = 64
centroid_ids = rng.integers(0, buckets, n)
centroids = np.stack([
    vectors[centroid_ids == b].mean(axis=0) if (centroid_ids == b).any() else np.zeros(dimensions)
    for b in range(buckets)
])
centroids /= np.maximum(np.linalg.norm(centroids, axis=1, keepdims=True), 1e-12)

def exact(query, k=10):
    scores = vectors @ query
    return set(np.argsort(scores)[::-1][:k].tolist())

def approximate(query, k=10, probe=4):
    nearest = np.argsort(centroids @ query)[::-1][:probe]
    candidates = np.flatnonzero(np.isin(centroid_ids, nearest))
    if len(candidates) < k:
        return set(candidates.tolist())
    scores = vectors[candidates] @ query
    chosen = candidates[np.argsort(scores)[::-1][:k]]
    return set(chosen.tolist())

queries = vectors[rng.integers(0, n, 40)]
print(f"{'probe':>6} {'searched':>10} {'recall@10':>11}")
for probe in [1, 2, 4, 8, 16, 64]:
    recalls, searched = [], []
    for query in queries:
        truth = exact(query)
        found = approximate(query, probe=probe)
        recalls.append(len(truth & found) / len(truth))
        nearest = np.argsort(centroids @ query)[::-1][:probe]
        searched.append(int(np.isin(centroid_ids, nearest).sum()))
    print(f"{probe:>6} {np.mean(searched):>10,.0f} {np.mean(recalls):>11.3f}")`} />

That is the entire bargain: search fewer candidates, miss some true neighbours. Probing every
bucket recovers exact results and exact cost. Real indexes — HNSW, IVF-PQ — are far better at the
trade than this toy, but the shape is identical, and **recall is a number you must measure**, not
a property you can assume.

## Recap

- An index is unit vectors, parallel metadata and a dot product. Exact search handles ~100k
  vectors comfortably.
- Apply a similarity floor, or you always return k results however irrelevant.
- **Pre-filter**, then search. Post-filtering an approximate index returns nothing when the filter
  is selective.
- Persist vectors as `.npy`, records as JSONL, and a manifest carrying the model and dimensions so
  the compatibility check survives a restart.
- Delete with a tombstone mask and compact offline; rebuilding the array per delete invalidates
  every position.
- Approximate search trades recall for speed. Measure the recall — never assume it.
