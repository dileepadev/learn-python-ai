pandas gives you a table with named columns, a labelled index, and a column-at-a-time way of
working that keeps loops out of your data code. Most of an AI project is spent here: loading a
dataset, finding out what is wrong with it, and reshaping it into what the model needs.

## A Series

A Series is a 1-D array with an index attached:

<Run id="dw-df-1" code={`import pandas as pd

scores = pd.Series([0.71, 0.88, 0.93, 0.42])
print(scores)
print()
print("values:", scores.values)
print("index: ", list(scores.index))
print("dtype: ", scores.dtype)`} />

The index does not have to be numbers, and that is the point — it lets you look things up by
name:

<Run id="dw-df-2" code={`import pandas as pd

scores = pd.Series(
    [0.71, 0.88, 0.93],
    index=["baseline", "tuned", "ensemble"],
    name="accuracy",
)

print(scores)
print()
print("one value: ", scores["tuned"])
print("best run:  ", scores.idxmax())
print("mean:      ", round(scores.mean(), 4))
print("above 0.8:", list(scores[scores > 0.8].index))`} />

## A DataFrame

A DataFrame is a dict of Series that share one index — a table:

<Run id="dw-df-3" code={`import pandas as pd

runs = pd.DataFrame({
    "run": ["baseline", "tuned", "ensemble", "distilled"],
    "accuracy": [0.71, 0.88, 0.93, 0.84],
    "latency_ms": [120, 340, 980, 95],
    "tokens": [412, 980, 2100, 380],
})

print(runs)
print()
print("shape:  ", runs.shape)
print("columns:", list(runs.columns))`} />

Real data usually arrives as a list of records — a JSON array, or the rows of a JSONL file — and
pandas takes that directly:

<Run id="dw-df-4" code={`import pandas as pd

records = [
    {"run": "baseline", "accuracy": 0.71, "model": "haiku"},
    {"run": "tuned", "accuracy": 0.88, "model": "opus"},
    {"run": "ensemble", "accuracy": 0.93, "model": "opus"},
]

runs = pd.DataFrame(records)
print(runs)
print()
print(runs.dtypes)`} />

## The five commands you always run

Before anything else, find out what you have:

<Run id="dw-df-5" code={`import pandas as pd
import numpy as np

rng = np.random.default_rng(0)
evaluations = pd.DataFrame({
    "question_id": range(1, 21),
    "model": rng.choice(["opus", "haiku"], size=20),
    "score": rng.random(20).round(3),
    "latency_ms": rng.integers(80, 900, size=20),
})

print("1. head -------------------------------")
print(evaluations.head(3))
print()
print("2. shape ------------------------------", evaluations.shape)
print()
print("3. dtypes -----------------------------")
print(evaluations.dtypes)
print()
print("4. describe ---------------------------")
print(evaluations.describe().round(3))
print()
print("5. value_counts -----------------------")
print(evaluations["model"].value_counts())`} />

<Callout type="tip">
`describe()` only summarises numeric columns by default. `describe(include="all")` adds the
others, and `info()` tells you the row count, the dtypes and how many values are non-null — the
fastest way to spot a column that is half empty.
</Callout>

## Columns

Selecting one column gives a Series; selecting a list of them gives a DataFrame:

<Run id="dw-df-7" code={`import pandas as pd

runs = pd.DataFrame({
    "run": ["baseline", "tuned", "ensemble"],
    "accuracy": [0.71, 0.88, 0.93],
    "latency_ms": [120, 340, 980],
})

print(type(runs["accuracy"]).__name__)
print(runs["accuracy"])
print()
print(type(runs[["run", "accuracy"]]).__name__)
print(runs[["run", "accuracy"]])`} />

New columns are computed from existing ones, a whole column at a time:

<Run id="dw-df-8" code={`import pandas as pd

runs = pd.DataFrame({
    "run": ["baseline", "tuned", "ensemble"],
    "accuracy": [0.71, 0.88, 0.93],
    "latency_ms": [120, 340, 980],
    "tokens": [412, 980, 2100],
})

runs["tokens_per_second"] = runs["tokens"] / (runs["latency_ms"] / 1000)
runs["grade"] = (runs["accuracy"] >= 0.85).map({True: "pass", False: "fail"})

print(runs.round(1))
print()
print(runs.drop(columns=["tokens_per_second"]).columns.tolist())`} />

Note that no loop appeared. `runs["tokens"] / (runs["latency_ms"] / 1000)` is a vectorised
operation over the whole column, exactly like NumPy.

## The index

The index labels the rows. Setting a meaningful one makes lookups and joins natural:

<Run id="dw-df-9" code={`import pandas as pd

runs = pd.DataFrame({
    "run": ["baseline", "tuned", "ensemble"],
    "accuracy": [0.71, 0.88, 0.93],
})

print(runs.index)
print()

indexed = runs.set_index("run")
print(indexed)
print()
print("look up a row:", indexed.loc["tuned", "accuracy"])
print()
print("and back again:")
print(indexed.reset_index())`} />

<Callout type="warning">
After filtering or sorting, the index keeps the *original* row labels — so a filtered frame can
start at row 7. That is usually helpful, because it tells you where a row came from. When it
is not, `reset_index(drop=True)` renumbers from zero and throws the old labels away.
</Callout>

<Run id="dw-df-10" code={`import pandas as pd

runs = pd.DataFrame({
    "run": ["a", "b", "c", "d", "e"],
    "accuracy": [0.3, 0.9, 0.5, 0.95, 0.6],
})

good = runs[runs["accuracy"] > 0.5]
print(good)
print()
print(good.reset_index(drop=True))`} />

## Sorting

<Run id="dw-df-11" code={`import pandas as pd

runs = pd.DataFrame({
    "run": ["baseline", "tuned", "ensemble", "distilled"],
    "model": ["haiku", "opus", "opus", "haiku"],
    "accuracy": [0.71, 0.88, 0.93, 0.84],
})

print(runs.sort_values("accuracy", ascending=False))
print()
print(runs.sort_values(["model", "accuracy"], ascending=[True, False]))
print()
print("top 2:")
print(runs.nlargest(2, "accuracy"))`} />

## Reading and writing

<Run id="dw-df-12" code={`import pandas as pd
from pathlib import Path

runs = pd.DataFrame({
    "run": ["baseline", "tuned"],
    "accuracy": [0.71, 0.88],
})

runs.to_csv("runs.csv", index=False)      # index=False: do not write the row numbers
print(Path("runs.csv").read_text())

loaded = pd.read_csv("runs.csv")
print(loaded)
print()

runs.to_json("runs.jsonl", orient="records", lines=True)
print(Path("runs.jsonl").read_text())
print(pd.read_json("runs.jsonl", lines=True))`} />

<Callout type="ai" title="Why this matters for AI">
An evaluation run produces one row per example: the question, the model's answer, whether it was
right, how long it took and what it cost. Kept as JSONL and loaded into a DataFrame, every
question you have about the run becomes one line — accuracy by model, the slowest 1%, whether
long prompts fail more often. Writing that analysis as loops over dictionaries is how eval
harnesses become unmaintainable.
</Callout>

## Recap

- A Series is a labelled 1-D array; a DataFrame is a set of Series sharing one index.
- `pd.DataFrame(records)` turns a list of dicts — the shape JSONL arrives in — into a table.
- Always run `head`, `shape`, `dtypes`, `describe` and `value_counts` before anything else;
  `info()` shows where values are missing.
- `df["col"]` is a Series, `df[["col"]]` is a DataFrame.
- Build new columns from whole columns, never in a loop.
- Filtering preserves the original index; `reset_index(drop=True)` renumbers when you want that.
- `to_csv(..., index=False)` and `to_json(..., orient="records", lines=True)` round-trip cleanly.
