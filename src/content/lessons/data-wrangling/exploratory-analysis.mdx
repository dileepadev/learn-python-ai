Every calculation in this module is easy to get arithmetically right and still be misled by.
This lesson is about the four failures that produce a correct number and a wrong conclusion.

## Start with the shape, not the mean

<Run id="dw-eda-1" code={`import pandas as pd
import numpy as np

rng = np.random.default_rng(0)

# Two very different realities with the same average.
uniform = rng.normal(0.70, 0.05, 500).clip(0, 1)
bimodal = np.concatenate([rng.normal(0.97, 0.02, 350), rng.normal(0.07, 0.03, 150)]).clip(0, 1)

for name, scores in [("uniform", uniform), ("bimodal", bimodal)]:
    print(f"{name:8} mean {scores.mean():.3f}  median {np.median(scores):.3f}  "
          f"std {scores.std():.3f}  p10 {np.quantile(scores, 0.1):.3f}")

print(f"  uniform {np.mean(uniform < 0.5):.1%}")

Both average about 0.70. One model is mediocre at everything; the other is excellent at 70% of
questions and completely fails the rest. They need different work, and the mean cannot tell them
apart.

## Simpson's paradox

A model can be worse overall and better on every single subgroup:

<Run id="dw-eda-3" code={`import pandas as pd

results = pd.DataFrame([
    {"model": "A", "difficulty": "easy", "correct": 90, "total": 100},
    {"model": "A", "difficulty": "hard", "correct": 5, "total": 10},
    {"model": "B", "difficulty": "easy", "correct": 19, "total": 20},
    {"model": "B", "difficulty": "hard", "correct": 60, "total": 100},
])

results["accuracy"] = results["correct"] / results["total"]
print(results)
print()

overall = results.groupby("model")[["correct", "total"]].sum()
overall["accuracy"] = (overall["correct"] / overall["total"]).round(4)
print("overall:")
print(overall)`} />

Model B wins on easy questions (0.95 against 0.90) and on hard questions (0.60 against 0.50), and
loses overall. Nothing is wrong with the arithmetic — the two models were simply given different
mixes of questions:

<Run id="dw-eda-4" code={`import pandas as pd

results = pd.DataFrame([
    {"model": "A", "difficulty": "easy", "correct": 90, "total": 100},
    {"model": "A", "difficulty": "hard", "correct": 5, "total": 10},
    {"model": "B", "difficulty": "easy", "correct": 19, "total": 20},
    {"model": "B", "difficulty": "hard", "correct": 60, "total": 100},
])

mix = results.pivot_table(index="model", columns="difficulty", values="total", aggfunc="sum")
mix["hard_share"] = (mix["hard"] / (mix["easy"] + mix["hard"])).round(3)
print(mix)
print()

# Reweight both models to the same question mix — the fair comparison.
weights = {"easy": 0.5, "hard": 0.5}
results["accuracy"] = results["correct"] / results["total"]
results["weight"] = results["difficulty"].map(weights)
balanced = results.groupby("model").apply(
    lambda g: (g["accuracy"] * g["weight"]).sum(), include_groups=False
)
print("accuracy on a 50/50 mix:")
print(balanced.round(4))`} />

<Callout type="ai" title="Why this matters for AI">
This is not a curiosity — it is the default state of model comparison. Two models are almost
never evaluated on the same mix of questions, languages, prompt lengths or users, and whichever
got the easier mix wins on the headline number. Before comparing two models, check that the
denominators match: `crosstab(model, difficulty)` takes one line and settles it. If the mixes
differ, either reweight or compare only within subgroups.
</Callout>

## Survivorship bias

The rows that are missing are often the rows that matter:

<Run id="dw-eda-5" code={`import pandas as pd
import numpy as np

rng = np.random.default_rng(0)
n = 500

questions = pd.DataFrame({
    "question_id": range(n),
    "prompt_tokens": rng.integers(100, 8000, n),
})
# Long prompts time out and produce no answer at all.
questions["answered"] = questions["prompt_tokens"] < 6000
questions["score"] = np.where(
    questions["answered"],
    (1 - questions["prompt_tokens"] / 12000 + rng.normal(0, 0.08, n)).clip(0, 1),
    np.nan,
)

answered = questions[questions["answered"]]

print(f"answered {len(answered)} of {n} questions")
print(f"mean score over answered only: {answered['score'].mean():.3f}")
print(f"mean score counting failures as 0: {questions['score'].fillna(0).mean():.3f}")
print()
print("mean prompt length:")
print(f"  answered {answered['prompt_tokens'].mean():7.0f} tokens")
print(f"  dropped  {questions.loc[~questions['answered'], 'prompt_tokens'].mean():7.0f} tokens")`} />

Reporting 0.72 over the answered subset is not a lie, but it answers a question nobody asked. The
number a user experiences counts the failures.

## Small groups are noise

<Run id="dw-eda-6" code={`import pandas as pd
import numpy as np

def wilson_interval(correct, total, z=1.96):
    """A confidence interval for a proportion that behaves at small n."""
    if total == 0:
        return (0.0, 1.0)
    p = correct / total
    denominator = 1 + z ** 2 / total
    centre = (p + z ** 2 / (2 * total)) / denominator
    spread = z * np.sqrt(p * (1 - p) / total + z ** 2 / (4 * total ** 2)) / denominator
    return (max(0.0, centre - spread), min(1.0, centre + spread))

groups = pd.DataFrame([
    {"language": "en", "correct": 340, "total": 400},
    {"language": "si", "correct": 3, "total": 3},
    {"language": "ta", "correct": 7, "total": 12},
    {"language": "fr", "correct": 46, "total": 60},
])
groups["accuracy"] = (groups["correct"] / groups["total"]).round(3)
groups[["low", "high"]] = [wilson_interval(r.correct, r.total) for r in groups.itertuples()]
groups["width"] = (groups["high"] - groups["low"]).round(3)

print(groups.round(3).sort_values("accuracy", ascending=False))`} />

Sinhala tops the table at 100% — from three questions, with an interval running from 0.44 to
1.00. It is entirely consistent with that model being worse than every other language.

<Callout type="tip">
Put an interval, or at least the group size, next to every per-group number you report. A table
of accuracies without denominators invites exactly the wrong conclusion, and it takes one extra
column to prevent.
</Callout>

## Slicing until something looks real

If you test twenty slices at the 5% level, you expect one false positive even when nothing is
happening:

<Run id="dw-eda-7" code={`import numpy as np

rng = np.random.default_rng(3)

# One model, no real differences: every slice is the same coin.
slices = [f"slice-{i}" for i in range(20)]
true_rate = 0.70
n_per_slice = 60

observed = {name: rng.binomial(n_per_slice, true_rate) / n_per_slice for name in slices}

best = max(observed, key=observed.get)
worst = min(observed, key=observed.get)

print(f"true rate for every slice: {true_rate}")
print(f"best slice:  {best} at {observed[best]:.3f}")
print(f"worst slice: {worst} at {observed[worst]:.3f}")
print(f"spread purely from noise: {observed[best] - observed[worst]:.3f}")
print()
print("standard error of one slice:", round(np.sqrt(true_rate * (1 - true_rate) / n_per_slice), 4))`} />

An 18-point gap, entirely from chance. If you had gone looking for the slice where the model
underperforms, you would have found one and written a ticket about it.

<Callout type="warning">
Decide which slices you care about **before** you look. If you must explore, treat anything you
find as a hypothesis and confirm it on a fresh sample — the same discipline as a held-out test
set, applied to your own analysis.
</Callout>

## Correlation is not the mechanism

<Run id="dw-eda-8" code={`import pandas as pd
import numpy as np

rng = np.random.default_rng(0)
n = 400

# Long prompts arrive with hard questions AND cause slow responses.
difficulty = rng.random(n)
prompt_tokens = 200 + difficulty * 6000 + rng.normal(0, 300, n)
latency = 50 + prompt_tokens * 0.05 + rng.normal(0, 40, n)
score = (1 - difficulty + rng.normal(0, 0.1, n)).clip(0, 1)

frame = pd.DataFrame({
    "difficulty": difficulty,
    "prompt_tokens": prompt_tokens,
    "latency_ms": latency,
    "score": score,
})

print(frame.corr(numeric_only=True).round(3))
print()
print("Latency correlates with a low score at", round(frame["latency_ms"].corr(frame["score"]), 3))
print("...but within a narrow difficulty band:")
band = frame[(frame["difficulty"] > 0.45) & (frame["difficulty"] < 0.55)]
print("  correlation:", round(band["latency_ms"].corr(band["score"]), 3), f"(n={len(band)})")`} />

Slow answers score badly — but making the model faster would not help. Difficulty drives both.

## Recap

- Look at the distribution first. Two models with the same mean can need completely different
  work.
- Simpson's paradox is the normal case in model comparison: check the group sizes match, and
  reweight or compare within subgroups when they do not.
- Ask what got filtered out before the number was computed — the unanswered questions are usually
  the interesting ones.
- Report group sizes or intervals. A 100% from three examples is consistent with being the worst
  group you have.
- Choose your slices before you look, and confirm anything you find by exploring on fresh data.
- A correlation usually has a third variable behind it; check within a narrow band of the
  suspected confounder.
