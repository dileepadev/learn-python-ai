Almost every question you ask of a dataset starts with "the rows where…". pandas has two
selectors and one filtering idiom, and knowing which is which saves a lot of confusion.

## loc and iloc

`loc` works with **labels** — the index values and column names. `iloc` works with **integer
positions**, like a NumPy array:

<Run id="dw-sel-2" code={`import pandas as pd

evaluations = pd.DataFrame({
    "question": ["q1", "q2", "q3", "q4"],
    "score": [0.95, 0.72, 0.61, 0.40],
}).set_index("question")

print("loc by label:")
print(evaluations.loc["q2"])
print()
print("loc, rows and a column:", evaluations.loc["q2", "score"])
print("loc, a label range:   ", list(evaluations.loc["q2":"q3", "score"]))
print()
print("iloc by position:     ", evaluations.iloc[1, 0])
print("iloc, a slice:        ", list(evaluations.iloc[1:3, 0]))`} />

<Callout type="warning">
A `loc` slice **includes** its endpoint; an `iloc` slice excludes it, like every other Python
slice. `loc["q2":"q3"]` gives two rows; `iloc[1:3]` also gives two, but for a different reason.
</Callout>

## Filtering

A comparison on a column gives a boolean Series, and passing it back selects the `True` rows:

<Run id="dw-sel-3" code={`import pandas as pd

evaluations = pd.DataFrame({
    "question": ["q1", "q2", "q3", "q4", "q5", "q6"],
    "model": ["opus", "haiku", "opus", "haiku", "opus", "haiku"],
    "difficulty": ["easy", "easy", "hard", "hard", "medium", "medium"],
    "score": [0.95, 0.72, 0.61, 0.40, 0.88, 0.55],
})

mask = evaluations["score"] >= 0.7
print(mask)
print()
print(evaluations[mask])
print()
print("how many passed:", mask.sum(), "of", len(mask))`} />

Combine conditions with `&`, `|` and `~`, parenthesising each one — exactly as in NumPy:

<Run id="dw-sel-4" code={`import pandas as pd

evaluations = pd.DataFrame({
    "question": ["q1", "q2", "q3", "q4", "q5", "q6"],
    "model": ["opus", "haiku", "opus", "haiku", "opus", "haiku"],
    "difficulty": ["easy", "easy", "hard", "hard", "medium", "medium"],
    "score": [0.95, 0.72, 0.61, 0.40, 0.88, 0.55],
})

hard_failures = evaluations[(evaluations["difficulty"] == "hard") & (evaluations["score"] < 0.7)]
print(hard_failures)
print()

either = evaluations[(evaluations["model"] == "opus") | (evaluations["score"] > 0.7)]
print("opus or scored well:", list(either["question"]))
print("not opus:           ", list(evaluations[~(evaluations["model"] == "opus")]["question"]))`} />

## isin, between and .str

<Run id="dw-sel-5" code={`import pandas as pd

documents = pd.DataFrame({
    "path": ["docs/intro.md", "docs/api.md", "blog/launch.md", "docs/faq.txt"],
    "language": ["en", "en", "si", "en"],
    "tokens": [412, 980, 2100, 120],
})

print(documents[documents["language"].isin(["si", "ta"])])
print()
print(documents[documents["tokens"].between(100, 1000)])
print()
print(documents[documents["path"].str.startswith("docs/")])
print()
print(documents[documents["path"].str.endswith(".md")])
print()
print("extracted names:", list(documents["path"].str.split("/").str[-1]))`} />

The `.str` accessor applies a string method down the whole column. `.str.contains`,
`.str.lower`, `.str.strip`, `.str.replace` and `.str.len` cover most text cleaning.

<Run id="dw-sel-6" code={`import pandas as pd

documents = pd.DataFrame({
    "title": ["  Retrieval Basics ", "EMBEDDINGS explained", "Chunking  strategies"],
})

documents["clean"] = documents["title"].str.strip().str.lower()
documents["words"] = documents["clean"].str.split().str.len()
documents["mentions_chunk"] = documents["clean"].str.contains("chunk")

print(documents)`} />

## query

For a long chain of conditions, `query` reads better — column names become bare names:

<Run id="dw-sel-7" code={`import pandas as pd

evaluations = pd.DataFrame({
    "question": ["q1", "q2", "q3", "q4", "q5", "q6"],
    "model": ["opus", "haiku", "opus", "haiku", "opus", "haiku"],
    "difficulty": ["easy", "easy", "hard", "hard", "medium", "medium"],
    "score": [0.95, 0.72, 0.61, 0.40, 0.88, 0.55],
    "latency_ms": [320, 90, 410, 85, 350, 95],
})

print(evaluations.query("score > 0.7 and latency_ms < 400"))
print()
print(evaluations.query("difficulty in ['hard', 'medium'] and model == 'opus'"))
print()

threshold = 0.6
print(evaluations.query("score > @threshold").shape)`} />

An `@` prefix reaches out to a Python variable. Note that `query` uses `and`/`or`, not `&`/`|` —
it is a small expression language of its own.

## Assigning

Assign through `.loc`, naming both the rows and the column:

<Run id="dw-sel-8" code={`import pandas as pd

evaluations = pd.DataFrame({
    "question": ["q1", "q2", "q3", "q4"],
    "score": [0.95, 0.72, 0.61, 0.40],
})

evaluations.loc[evaluations["score"] < 0.7, "verdict"] = "review"
evaluations.loc[evaluations["score"] >= 0.7, "verdict"] = "accept"

print(evaluations)
print()

# A whole column at once:
evaluations["score"] = evaluations["score"].round(1)
print(evaluations)`} />

The mistake to know about is **chained assignment** — selecting twice and assigning into the
second selection:

<Run id="dw-sel-9" code={`import pandas as pd

evaluations = pd.DataFrame({
    "question": ["q1", "q2", "q3"],
    "score": [0.95, 0.72, 0.40],
})

# Two separate operations: the filter makes a new frame, and the assignment
# lands on that temporary. The original is untouched.
evaluations[evaluations["score"] < 0.5]["score"] = 0.0
print(evaluations)
print()

# What you meant:
evaluations.loc[evaluations["score"] < 0.5, "score"] = 0.0
print(evaluations)`} />

<Callout type="warning">
Chained assignment never modifies the original frame — `df[mask]["col"] = value` writes into a
temporary that is discarded immediately. Under pandas' copy-on-write behaviour this is
consistently a no-op rather than a coin flip, which is better, but it is still silent. One
`.loc[rows, column] = value` is always the right form.
</Callout>

## where, mask and assign

<Run id="dw-sel-10" code={`import pandas as pd

evaluations = pd.DataFrame({
    "question": ["q1", "q2", "q3", "q4"],
    "score": [0.95, 0.72, 0.61, 0.40],
    "latency_ms": [320, 90, 410, 85],
})

# where: keep the value where the condition is True, replace it otherwise.
print(evaluations["score"].where(evaluations["score"] > 0.7, 0.0))
print()
# mask is the inverse.
print(evaluations["score"].mask(evaluations["score"] > 0.7, 1.0))
print()

# assign returns a new frame, so several derived columns chain cleanly.
summary = (
    evaluations
    .assign(passed=lambda df: df["score"] >= 0.7)
    .assign(seconds=lambda df: df["latency_ms"] / 1000)
    .sort_values("score", ascending=False)
    .reset_index(drop=True)
)
print(summary)`} />

<Callout type="ai" title="Why this matters for AI">
Every claim about a model is a filtered slice: accuracy on hard questions, latency at the 95th
percentile, failures where the prompt was over 4,000 tokens. Being able to express those slices
directly is what lets you answer "where is it actually going wrong?" in one line instead of an
afternoon. The chained-assignment trap matters here too — a labelling script that silently fails
to write leaves you evaluating against data you think you fixed.
</Callout>

## Recap

- `loc` selects by label and its slices include the endpoint; `iloc` selects by position and
  excludes it.
- A comparison gives a boolean Series; index with it to filter, and combine with `&`, `|`, `~`,
  parenthesising each condition.
- `isin`, `between` and the `.str` accessor cover most of what masks need.
- `query("score > 0.7 and latency_ms < 400")` reads better for long conditions, and `@name`
  reaches a Python variable.
- Assign with `df.loc[rows, column] = value`. Chained assignment writes to a temporary and is
  silently lost.
- `assign` returns a new frame, so derived columns chain readably.
