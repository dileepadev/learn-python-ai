A dictionary maps **keys** to **values**. Where a list answers "what is at position 3?", a
dictionary answers "what is the accuracy?".

<Run id="f-dict-1" code={`person = {"name": "Dileepa", "age": 28, "city": "Kurunegala"}

print(person)
print(type(person))
print(len(person))`} />

## Looking things up

<Run id="f-dict-2" code={`person = {"name": "Dileepa", "age": 28, "city": "Kurunegala"}

print(person["name"])
print(person["age"])

print(person["country"])  # missing key -> KeyError`} />

Square brackets raise `KeyError` when the key is absent. `.get()` returns `None` instead — or a
default you choose:

<Run id="f-dict-3" code={`person = {"name": "Dileepa", "age": 28}

print(person.get("country"))
print(person.get("country", "Sri Lanka"))
print("age" in person, "country" in person)`} />

<Callout type="ai" title="Why this matters for AI">
API responses are dictionaries, and optional fields are genuinely optional. Reaching for
<code>response["usage"]["cache_read_tokens"]</code> works right up until a response omits it.
<code>.get(..., 0)</code> on anything that might be missing turns a crash into a sensible
default.
</Callout>

## Changing a dictionary

<Run id="f-dict-4" code={`person = {"name": "Dileepa", "age": 28, "city": "Kurunegala"}

person["age"] = 29                # update
person["country"] = "Sri Lanka"   # add
print(person)

del person["city"]                # remove
print(person)

removed = person.pop("country")   # remove and return
print(removed, "->", person)

person.update({"role": "developer", "age": 30})  # merge in several
print(person)`} />

Keys are unique. Assigning to an existing key replaces its value — and a literal with a
repeated key simply keeps the last one:

<Run id="f-dict-5" code={`duplicate = {"key": "first", "key": "second"}
print(duplicate)`} />

## Iterating

<Run id="f-dict-6" code={`scores = {"baseline": 0.71, "tuned": 0.88, "ensemble": 0.93}

print("keys:  ", list(scores.keys()))
print("values:", list(scores.values()))
print("items: ", list(scores.items()))

print()
for name in scores:                    # iterating gives you keys
    print(name)

print()
for name, score in scores.items():     # the pattern you want most often
    print(f"{name:<10} {score:.0%}")`} />

Dictionaries keep insertion order, so what you put in first comes out first. Sorting works
through `sorted` on the items:

<Run id="f-dict-7" code={`scores = {"baseline": 0.71, "tuned": 0.88, "ensemble": 0.93}

for name, score in sorted(scores.items(), key=lambda kv: kv[1], reverse=True):
    print(f"{name:<10} {score:.0%}")

print()
print("best:", max(scores, key=scores.get))`} />

## Dictionaries of dictionaries

Real data nests. This is exactly the shape of a JSON API response:

<Run id="f-dict-8" code={`response = {
    "id": "msg_017",
    "model": "claude-opus-5",
    "content": [{"type": "text", "text": "Hello!"}],
    "usage": {"input_tokens": 412, "output_tokens": 37},
}

print(response["model"])
print(response["content"][0]["text"])
print(response["usage"]["input_tokens"])

total = response["usage"]["input_tokens"] + response["usage"]["output_tokens"]
print(f"total tokens: {total}")

# Safe navigation when the shape is not guaranteed:
cached = response.get("usage", {}).get("cache_read_tokens", 0)
print(f"cached tokens: {cached}")`} />

## Building dictionaries

<Run id="f-dict-9" code={`names = ["baseline", "tuned", "ensemble"]
values = [0.71, 0.88, 0.93]

# From two sequences:
scores = dict(zip(names, values))
print(scores)

# A dict comprehension:
squares = {n: n * n for n in range(1, 6)}
print(squares)

# Filtering one dictionary into another:
good = {name: score for name, score in scores.items() if score > 0.8}
print(good)`} />

## Counting things

Counting occurrences is so common that the standard library has a tool for it:

<Run id="f-dict-10" code={`from collections import Counter

words = "the quick brown fox jumps over the lazy dog the fox".split()

counts = Counter(words)
print(counts.most_common(3))

# The manual version, for comparison:
manual = {}
for word in words:
    manual[word] = manual.get(word, 0) + 1
print(manual["the"], manual["fox"])`} />

<Callout type="tip">
`manual.get(word, 0) + 1` is the idiom for "increment, starting from zero". It avoids having to
check whether the key exists first.
</Callout>

## Recap

- Dictionaries map unique keys to values and preserve insertion order.
- `d[key]` raises on a missing key; `d.get(key, default)` does not.
- `.items()` is what you want in a `for` loop most of the time.
- Nested dictionaries are exactly how JSON and API responses are shaped.
- `Counter` and `d.get(k, 0) + 1` are the two ways to count things.
