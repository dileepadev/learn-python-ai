An **expression** is anything that produces a value. `2 + 2` is an expression; so is
`name.upper()` and `score > 0.9`. Operators are how you build them.

## Arithmetic

<Run id="f-op-1" code={`a = 11
b = 5

print("a + b  =", a + b)
print("a - b  =", a - b)
print("a * b  =", a * b)
print("a / b  =", a / b)    # true division -> always a float
print("a // b =", a // b)   # floor division -> drops the remainder
print("a %  b  =", a % b)   # modulo -> the remainder
print("a ** b =", a ** b)   # exponent`} />

Two of those deserve attention.

**`/` always returns a float**, even when the answer is whole. `10 / 2` is `5.0`, not `5`.
Use `//` when you want an integer result.

**`%` (modulo) gives the remainder**, and it is more useful than it looks:

<Run id="f-op-2" code={`for n in range(1, 11):
    kind = "even" if n % 2 == 0 else "odd"
    print(n, kind)

print()
# Modulo also wraps values around a range — useful for cycling.
colours = ["red", "green", "blue"]
for i in range(7):
    print(i, colours[i % len(colours)])`} />

<Callout type="ai">
Batching is modulo arithmetic. Splitting 1,000 documents into batches of 32 gives
<code>1000 // 32</code> full batches and <code>1000 % 32</code> left over — exactly the
calculation every data loader makes.
</Callout>

### Operators on strings and lists

`+` and `*` also work on sequences, where they mean "join" and "repeat":

<Run id="f-op-3" code={`print("Hello" + " " + "World")
print("ab" * 3)
print([1, 2] + [3, 4])
print([0] * 5)
print("-" * 40)`} />

## Comparison

Comparisons produce `True` or `False`.

<Run id="f-op-4" code={`x, y = 10, 20

print(x == y)   # equal
print(x != y)   # not equal
print(x > y, x < y)
print(x >= 10, y <= 20)

# Python lets you chain them, and it reads exactly as it looks.
score = 0.85
print(0.8 <= score < 0.9)`} />

That chained form is genuinely Python-specific and worth using — `0.8 <= score < 0.9` is
clearer than `score >= 0.8 and score < 0.9`.

## Boolean logic

<Run id="f-op-5" code={`p, q = True, False

print("and:", p and q)
print("or: ", p or q)
print("not:", not p)`} />

### Truthiness

Every value can be used where a boolean is expected. Empty things are falsy; everything else is
truthy.

<Run id="f-op-6" code={`falsy = [False, None, 0, 0.0, "", [], {}, set()]

for value in falsy:
    print(f"{repr(value):<8} -> {bool(value)}")

print()
print(bool("0"), bool([0]), bool(" "))  # non-empty, so all True`} />

<Callout type="warning">
Note `bool("0")` is `True` — a non-empty string is truthy regardless of what is in it. This is
a classic bug when a config value arrives as text: <code>if enabled:</code> where
<code>enabled == "false"</code> passes happily.
</Callout>

### Short-circuiting

`and` and `or` stop as soon as the answer is known, and they return one of the *operands*, not
a boolean.

<Run id="f-op-7" code={`def expensive():
    print("  (expensive was called)")
    return True

print("A:")
result = False and expensive()   # expensive never runs
print(" ->", result)

print("B:")
result = True or expensive()     # expensive never runs
print(" ->", result)

print()
# Because they return an operand, 'or' makes a neat default:
user_input = ""
name = user_input or "anonymous"
print(name)`} />

That last pattern — `value or fallback` — is idiomatic Python for "use this unless it's empty".

## `==` versus `is`

`==` asks "are these equal?". `is` asks "are these the same object?". They are not the same
question.

<Run id="f-op-8" code={`a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a == b)   # same contents
print(a is b)   # different objects
print(a is c)   # same object

c.append(4)
print(a)        # a changed too, because c IS a`} />

The rule in practice: use `==` for values, and use `is` only with `None`, `True` and `False`.

<Run id="f-op-9" code={`value = None

print(value is None)      # correct
print(value == None)      # works, but not idiomatic`} />

## Compound assignment

<Run id="f-op-10" code={`c = 10
c += 5;  print("+= 5  ->", c)
c -= 3;  print("-= 3  ->", c)
c *= 2;  print("*= 2  ->", c)
c /= 4;  print("/= 4  ->", c)   # note: now a float
c //= 2; print("//= 2 ->", c)
c **= 3; print("**= 3 ->", c)`} />

Watch the type: `/=` turns an int into a float and it never turns back.

## Recap

- `/` always gives a float; `//` floors to an int; `%` gives the remainder.
- Comparisons chain: `0 <= x < 1` is valid and readable.
- Empty values are falsy; every other value is truthy — including the string `"0"`.
- `and`/`or` short-circuit and return an operand, which makes `value or default` idiomatic.
- Use `==` for values and reserve `is` for `None`, `True` and `False`.
