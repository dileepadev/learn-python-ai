The browser sandbox has no network access and nowhere safe to keep an API key, so the runnable

## The request

One HTTPS POST to `/v1/messages`, carrying JSON. That is the whole API — tools, streaming,
caching and structured output are all fields on this one request.

<Run id="llm-api-1" code={`import json

request = {
    "model": "claude-opus-5",
    "max_tokens": 16000,
    "system": "You are a terse assistant. Answer in one sentence.",
    "messages": [
        {"role": "user", "content": "What is a token?"},
    ],
}

print(json.dumps(request, indent=2))`} />

Four things to notice:

- **`model`** names the exact model. It is not a family or an alias you can leave vague.
- **`max_tokens`** is a hard ceiling on the *output*. Hit it and the reply stops mid-sentence.
- **`system`** is its own top-level field, not a message. It carries operator authority.
- **`messages`** alternates user and assistant turns, and must begin with `user`.

On your own machine that request is:

```python
import anthropic

client = anthropic.Anthropic()          # reads ANTHROPIC_API_KEY from the environment

response = client.messages.create(
    model="claude-opus-5",
    max_tokens=16000,
    system="You are a terse assistant. Answer in one sentence.",
    messages=[{"role": "user", "content": "What is a token?"}],
)
```

<Callout type="warning">
Never put the key in the source. `anthropic.Anthropic()` with no arguments reads it from the
environment, which is what you want everywhere — a laptop, CI, a container. A key in a commit is a
key you have to rotate.
</Callout>

`content` is a **list of blocks**, not a string. A plain answer is one `text` block; a reply that
calls a tool has `tool_use` blocks; a reply with thinking enabled has `thinking` blocks first. So
always iterate and check `block.type` rather than reaching for `content[0].text`:

<Run id="llm-api-3" code={`from types import SimpleNamespace

response = SimpleNamespace(content=[
    SimpleNamespace(type="thinking", thinking="The user wants a definition..."),
    SimpleNamespace(type="text", text="A token is a chunk of text."),
])

# Fragile: assumes the first block is text.
print("naive:", getattr(response.content[0], "text", "<no text on this block>"))

# Correct:
text = "".join(block.text for block in response.content if block.type == "text")
print("correct:", text)`} />

## stop_reason

Always check it before trusting the content:

<Run id="llm-api-4" code={`REASONS = {
    "end_turn": "Finished naturally. Use the content.",
    "max_tokens": "Ran out of room. The reply is truncated — raise max_tokens or stream.",
    "stop_sequence": "Hit one of your stop_sequences.",
    "tool_use": "Wants to call a tool. Execute it and send the result back.",
    "pause_turn": "A long server-side tool turn paused. Send it back to continue.",
    "refusal": "Declined on safety grounds. Check stop_details for the category.",

<Run id="llm-api-5" code={`from types import SimpleNamespace

def handle(response):
    if response.stop_reason == "refusal":
        category = getattr(response.stop_details, "category", None)
        return f"declined ({category})"
    if response.stop_reason == "max_tokens":
        return "truncated — retry with a larger max_tokens"
    if response.stop_reason == "tool_use":
        return "needs a tool result before it can finish"
    return "".join(b.text for b in response.content if b.type == "text")

cases = [
    SimpleNamespace(stop_reason="end_turn", stop_details=None,
                    content=[SimpleNamespace(type="text", text="All done.")]),
    SimpleNamespace(stop_reason="max_tokens", stop_details=None,
                    content=[SimpleNamespace(type="text", text="It was the best of ti")]),
    SimpleNamespace(stop_reason="refusal",
                    stop_details=SimpleNamespace(type="refusal", category="cyber"),
                    content=[]),
]

for case in cases:
    print(f"{case.stop_reason:12} -> {handle(case)}")`} />

<Callout type="warning">
`stop_details` is populated **only** when `stop_reason` is `"refusal"`, and is `None` otherwise —
so guard before reading it. And a truncated `max_tokens` reply is not an error: you get HTTP 200
and a plausible-looking half-sentence.
</Callout>

## The API is stateless

The server keeps nothing between calls. Whatever the model appears to "remember" is in the
`messages` list you resent:

<Run id="llm-api-6" code={`class RecordedClient:
    """Answers from a fixture, but reads the request exactly as the real API would."""

    def __init__(self, replies):
        self.replies = list(replies)
        self.requests = []

    def create(self, *, model, max_tokens, messages, system=None):
        self.requests.append({"messages": [dict(m) for m in messages], "system": system})
        return self.replies.pop(0)

client = RecordedClient([
    "Hello Dileepa, nice to meet you.",
    "Your name is Dileepa.",
])

messages = []

def ask(question):
    messages.append({"role": "user", "content": question})
    reply = client.create(model="claude-opus-5", max_tokens=1024, messages=messages)
    messages.append({"role": "assistant", "content": reply})
    return reply

print(ask("My name is Dileepa."))
print(ask("What is my name?"))

print()
print("what the second request actually carried:")
for turn in client.requests[1]["messages"]:
    print(f"  {turn['role']:9} {turn['content']}")`} />

The second request carried three turns. The model did not recall the name — it read it, again.

<Callout type="ai" title="Why this matters for AI">
Statelessness is the fact that shapes the cost of every conversational system you build. Turn
twenty resends turns one to nineteen, so input tokens grow quadratically with conversation
length: a chat that feels cheap at the start is expensive by the end, and eventually hits the
context window. Every technique later in this module — prompt caching, summarisation,
compaction, retrieval instead of stuffing — exists to manage that one consequence.
</Callout>

<Run id="llm-api-7" code={`def tokens_for_turn(turn_number, tokens_per_turn=200):
    """Input tokens for turn N when the whole history is resent each time."""
    return turn_number * tokens_per_turn

total = 0
print(f"{'turn':>5} {'input tokens':>13} {'cumulative':>12}")
for turn in [1, 5, 10, 20, 50]:
    running = sum(tokens_for_turn(t) for t in range(1, turn + 1))
    print(f"{turn:>5} {tokens_for_turn(turn):>13,} {running:>12,}")

fifty_turns = sum(tokens_for_turn(t) for t in range(1, 51))
print()
print(f"a 50-turn chat costs {fifty_turns:,} input tokens, not {50 * 200:,}")`} />

## Usage, and what it costs

<Run id="llm-api-8" code={`# Published rates, US dollars per million tokens.
PRICING = {
    "claude-opus-5":     {"input": 5.00,  "output": 25.00},
    "claude-sonnet-5":   {"input": 2.00,  "output": 10.00},
    "claude-haiku-4-5":  {"input": 1.00,  "output": 5.00},
}

def cost(model, input_tokens, output_tokens):
    rates = PRICING[model]
    return (input_tokens * rates["input"] + output_tokens * rates["output"]) / 1_000_000

usage = {"input_tokens": 12_400, "output_tokens": 850}

print(f"{'model':<18} {'cost':>10}  {'per 10k calls':>15}")
for model in PRICING:
    one = cost(model, usage["input_tokens"], usage["output_tokens"])
    print(f"{model:<18} {one:>10.5f}  {one * 10_000:>14.2f}")`} />

Output tokens cost about five times what input tokens cost, on every model. A prompt that asks
for a short answer is cheaper twice over — fewer output tokens now, and a shorter history to
resend later.

## A conversation, properly

<Run id="llm-api-9" code={`from types import SimpleNamespace

class RecordedClient:
    def __init__(self, replies):
        self.replies = list(replies)

    def create(self, **request):
        text = self.replies.pop(0)
        return SimpleNamespace(
            content=[SimpleNamespace(type="text", text=text)],
            stop_reason="end_turn",
            usage=SimpleNamespace(input_tokens=40 * len(request["messages"]), output_tokens=20),
        )

class Conversation:
    def __init__(self, client, system=None, model="claude-opus-5"):
        self.client = client
        self.system = system
        self.model = model
        self.messages = []
        self.input_tokens = 0
        self.output_tokens = 0

    def ask(self, question):
        self.messages.append({"role": "user", "content": question})
        response = self.client.create(
            model=self.model,
            max_tokens=16000,
            system=self.system,
            messages=self.messages,
        )
        if response.stop_reason == "refusal":
            self.messages.pop()
            return "[declined]"

        # Append the content blocks, not the extracted string: a reply may hold
        # thinking or tool_use blocks the next turn needs to see.
        self.messages.append({"role": "assistant", "content": response.content})
        self.input_tokens += response.usage.input_tokens
        self.output_tokens += response.usage.output_tokens
        return "".join(b.text for b in response.content if b.type == "text")

chat = Conversation(
    RecordedClient(["Retrieval augmented generation.", "It grounds answers in your documents."]),
    system="Answer in one short sentence.",
)

print(chat.ask("What does RAG stand for?"))
print(chat.ask("Why use it?"))
print()
print("turns stored:", len(chat.messages))
print(f"tokens: {chat.input_tokens} in, {chat.output_tokens} out")`} />

<Callout type="tip">
Append `response.content` — the list of blocks — to the history, not the extracted text. Once
thinking, tool use or compaction are involved, the blocks you dropped are exactly the ones the
next request needed.
</Callout>

## Recap

- Everything is one POST to `/v1/messages`: `model`, `max_tokens`, `system` and `messages`.
- `content` is a list of typed blocks — iterate and check `block.type` rather than indexing.
- Check `stop_reason` before trusting the content; `stop_details` exists only for `"refusal"`.
- The API is stateless, so a conversation resends its whole history and input tokens grow
  quadratically with its length.
- Output tokens cost about five times input tokens.
- Append `response.content` to the history, not the extracted string.
